# Standard library listing

`listing.json` lists every public item of the prelude and of `std.testing`, as the checker reads them in each edition, with the names of the server that only an import of `std.host` brings into scope listed under `std.host`. It does not list the standard modules `std.time`, `std.drive` and `std.limit` of edition `0.4`, nor `std.collections` of edition `0.5`: their specification is `spec/26`, `spec/27` and `spec/28`. Each listed item has its name, module, kind, the spec sections its doc comments cite, and one variant per run of editions in which its declaration and doc comments are the same. A variant holds the editions, the declaration without its body, and the doc comments.

**Unstable, not part of the specification.** The schema `una.std-listing/1` may change without notice. No `una` command prints it, and no tool should depend on it. The specification of the standard library is `spec/14` and `spec/20` to `spec/24`.

- **Generated.** `crates/una-cli/src/std_listing.rs` writes it from the standard modules (`crates/una-check/src/std/`), through the same per-edition source the checker loads. `crates/una-cli/tests/std_listing.rs` fails when this file is not current; `UNA_BLESS=1 cargo test -p una-cli --test std_listing` rewrites it.
- **Checked.** The same test requires a doc comment on every item in every edition, citing spec sections that exist. It also checks that each item is listed in exactly the editions in which `una check` resolves its name.
- **Built-in methods: `builtins.json`.** `.len`, the methods of maps (`spec/21 §2`), the conversions (`spec/18 §4`) and the wrapping, saturating and bit operations of fixed-width integers (`spec/18 §5`) have no declaration, so `crates/una-cli/src/std_builtins.rs` writes their signature lines and doc comments, in the same item shape, under the unstable schema `una.std-builtins/1`. The test keeps them in step with the checker (`una_check::builtin_methods`) both ways, and probes each written signature in every edition: a call with arguments of the written types bound to the written result type must check from the listed edition on and not before, and the same call with a wrongly typed argument or result must not.
- **The reference: `reference.json`** (#853). Hand-written, under the unstable schema `una.std-reference/1`, beside the generated listings: for each item, its area, what each parameter means, what it returns, its preconditions (`requires`, obligations that `una check` proves at each call, as `requires_note` says), when each variant of its failure kind is the failure, a kind's variants and their fields, what to use instead and when (from which edition, where the advice is newer than the item), related items, its cost where an accepted ADR or a spec section states it, in a cost table or in a sentence that the test lists (with the citation and the meaning of each term; una#852 is to state every item's), and an example. Items are named as `module name`. `crates/una-cli/tests/std_listing.rs` checks it against `listing.json` and `builtins.json`:
  - every item of both is described or named under `pending`, exactly once, and every entry has the fields its kind needs, none empty and no unknown key;
  - every prose text (`meaning`, `when`, `why`, `differs` and the notes) follows the rules of doc comments: one paragraph, with paired code spans and no HTML, link, heading, list or control character;
  - the parameters' names, the result type, the `requires` conditions and the failure kind's variants (as declared in the editions the entry describes) are those of the declaration; a parameter or receiver says "changed in place" exactly when it is declared `edit`; a built-in method, which has no declaration with `requires` lines, has exactly the `requires` that the table rows calling it in any spec section give, as `requires C`, as `requires` followed by `C`, or as the word requires followed by `C` (spec/28 §9, #904), with each argument's name replaced by its label (`0 <= by and by < w` for the shifts); such a row that says `requires` in another form, or a declaration with `requires` that no row states, is refused; a condition that prose restates in a code span is, verbatim, part of a contract of the declaration or of a spec section the item cites, and a constraint that prose names, such as `Ord`, is one of the declaration's;
  - when the declaration differs between editions, `describes` names the editions of the declaration the entry describes, and `earlier` says, for each other declaration, how it differs: it quotes in code spans each line that the earlier declaration has and the described one lacks, and each line after the first that the described one has and the earlier one lacks;
  - a function that has the effects and the failures of a parameter (both `uses of p` and `fails of p`) says so under `effects_of`, naming that parameter; a declaration with only one of the two clauses is refused, since `effects_of` says both;
  - a built-in method names its receiver's type under `receiver`, or each one under `receivers` (as `.len` does), as its `where` lines give them, and each receiver's meaning names it as its signature line does (`m`); when its signature lines differ beyond the receiver (as `has` on a `Map` and on a `Set`), it gives instead `by_receiver`, an object from each receiver type of its `where` lines, exactly those, to that receiver's `meaning`, `params`, `returns` and, when it has any, `requires`, each checked against that receiver's signature line, and no `receiver`, `receivers`, `params`, `returns` or `requires` of its own; a cost stated for one receiver says which under `on`, the receiver that the test's `COST_ON` ties to the source's row or sentence;
  - a kind describes its variants (a sum: constructors after `=`, with a leading `|`, several of them or fields), its fields (a record: lines `name: Type`) or its definition (anything else after `=`, as for `Nat`), as its declaration has them;
  - every item it names is listed and exists in every edition of the entry's item, or from its `from_edition` on, which must be the first edition where both exist;
  - every cost is, verbatim, the one cell of the item's row in the cost column (headed `Time`) of the first such table in the Decision section of the accepted ADR, or in the spec section, that it cites, or the cost that the test's `STATED_COSTS`, which review keeps, gives the item from a sentence of that source, each part of it between commas being words of the sentence, so that each item gets the phrase about it; every accepted ADR and every spec section is searched, so an item whose row a cost table has, or that `STATED_COSTS` names, must carry its cost; and each symbol inside its `O(...)`, other than `log`, is a defined term;
  - a predicate is checked as a function: its parameters, its result and its preconditions;
  - a capability lists its `operations` (#903), one per `op` line of its declaration and in its order: each with its `params` (`[]` when it has none) and `returns` as the declaration has them; `fails` exactly when the operation declares a failure kind, with the kind's variants in the newest edition the entry describes, where a variant that an earlier described edition lacks says in its `when` the edition it comes in (`` edition `0.4` ``); `accepts` exactly when the operation has an `accepts` line, with its label; and `grant`, one of the grant specs of `spec/13 §5` with its placeholders as that section writes them (`files:<path>:read`), `<methods>` being a list of the methods of `spec/24 §2`. The checker decides what a grant gives: in a probe package whose `main` uses the operation, of edition 0.2 or of the capability's first edition when that is later (an `ita.una` from edition 0.4, where a `serve:` spec is a `serve` line and only the specs written as a word or a `serve` line are probed), no grant is U3012, the operation's grant alone is not, and no other grant spec that gives the operation gives a strict subset of what its grant gives (`each_operation_is_given_by_its_grant_and_by_no_narrower_one`, one `una check` at tier 0 per grant spec and operation);
  - each example's `una.toml` is the same minimal manifest (edition 0.2, a `shop` entry, the `console` grant), except that an example whose code uses `checked` exactly once also allows that one use, `[escape_budget] checked_per_module = 1`, since code calls an opaque predicate only as the predicate of `checked` (`spec/03 §4`); and its `verification.lock` is the repository's own; an example of an item that edition 0.2 does not have is of the item's first edition instead (#904): `edition = "0.3"` in the same `una.toml`, and from edition 0.4 an `ita.una` of the same package, entry and grant, with no `checked`, and the `ita.lock` that `una ita lock` writes, with no `una.toml` or `verification.lock`;
  - each example, a package under `examples/<module>/<item>/` in a store's domain, checks clean in canonical form and prints its `expected/output.txt`; code that `main` reaches, outside comments and texts, names its item as a call (a kind's example names the kind and its variants, a capability's names the capability, a constant's names it as a value, and an item of `std.testing`, which only examples and the handlers they install may call (`spec/14 §4`), or one that `main` cannot reach under the examples' manifest (the test's `EXAMPLE_ONLY`: `HttpServer`, which only a `serve` grant gives, and `Exchange`, whose reply right only the host or `test_exchange` makes), is named anywhere in its code, and `una test` passes the example's own examples or tests); and with the item renamed, it no longer checks. Where a prelude function and a built-in method share a name (`set`), a function of that name declared beside the example, which shadows the prelude function and not the built-in method, stops the prelude function's example from checking and leaves the built-in method's checking, whatever types the code writes or infers. Otherwise these checks are syntactic: that the printed output depends on the call is left to review.
- **Not listed.** Operators, comparisons, equality and interpolation are not methods (`spec/14 §2`).
- **Published.** The site bundle (`scripts/site-bundle.sh`) carries this directory, from which the website builds its standard library pages.
