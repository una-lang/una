# Una 0.5.1

Una 0.5.1 is the second published increment of release R0.5: security fixes, clearer diagnostics and reports, and an installer that cleans up after an upgrade. The language and its editions are those of 0.5.0, and so are the targets: no construct is added, and a program that 0.5.0 accepts needs no edit, except one that starts tasks and releases data above `internal` through a policy (see below). One rule of the schedule changes: in the interpreter and under `--virtual-time`, a task that quiet code starts is held by its `tasks` statement (ADR 0117, amendment of 2026-11-22), which closes an information-flow channel and moves public events only in programs where quiet code starts tasks. A policy call is now a check point of that schedule, so a program that starts tasks and gives a policy's `via` data above `internal` is refused. A few answers at the edges of `una lsp`, `una report` and the checker change, as listed below. Editions `0.4` and `0.5` stay previews.

## Highlights

This release adds no language feature. What a user gains:

- **Reports that show the whole authority** (#864). `una report` prints each `uses` entry of `authority` and `handler_authority` as the header writes it, with the condition and the label of each operation, `op gives label where C`, as `una contract` shows it. A header with `uses @printer: Printer[print_label where not dry_run]` was reported as `@printer: Printer[print_label]`, more authority than it grants.
- **Repairs that name what to write** (#837, #1931). U3013 advises the form that resolves it where the call stands: under `attempt`, in a lambda, in a conditional value, in a `together` branch or on a `do` line, where binding the result with `let` first would not resolve it or would run the call every time. `una explain U3013` lists the cases. U3021's repair names the caller's binding instead of a placeholder, and, when no grant of a binding can keep both, names a handler whose own `uses` lie within the ceiling, as U3020 does.
- **`result`, `it` and `error` in a lambda are diagnostics** (#1989). In the body of a lambda they name no value, wherever the lambda is written. The checker now reports U2012 for `result` and U2013 for `it` and `error` at the use, where 0.4.0 and 0.5.0 rejected the package with the internal error U8001. Pass the value the body needs as an argument.
- **An upgrade leaves no old files** (#1992). `install.sh`, run over an earlier installation, removes the files of the earlier installation that the new one does not hold, such as the `bin/z3` link of a release before 0.4.0, and the directories left empty, and names them. Upgrading from 0.3.16 and then uninstalling leaves nothing in `~/.una`.
- **Clearer help** (#2070). The help of `--workers`, `--io-threads` and `--file-threads`, of `--from`, of `una ita`, `una migrate` and `una run`, and the installer's messages say what this release does.

## Changes that may need an edit

This release changes no construct of edition `0.4`, and one kind of program is now refused. These behaviors change:

- **A policy call above `internal` in a program that starts tasks is refused** (#2214). A policy call runs its `via`, whose code the label rules do not check, and it is now a check point of the schedule of started tasks (`spec/27 §8` rule 5). In a package that starts tasks, a policy call whose argument is labeled above `internal` is now U4002 at the call, whatever the policy's `to` label; 0.5.0 accepted it with an empty report. At `internal` the call is accepted and listed in the report's `information.timing` as a `task switch`, and with a `public` argument nothing changes.
- **`una lsp` reports a refusal as U7016 and exits with code 1.** Each message of the editor that the language server refuses is now a diagnostic with the new code U7016: on standard error one line, `error[U7016]: <message>`, or with `--json` one `una.diagnostic/1` document a line, and the `window/showMessage` sent to the editor carries the same code and text. A session that reported a refusal exits with code 1, as every diagnostic with a code does (ADR 0036). In 0.5.0 a refusal that ended the session exited with code 2, and a session that dropped a message and went on exited with 0; both now exit with 1. A failure to read the input, or to write the notification, exits with code 2. Input that ends inside a header, which ended the session silently with exit code 0, is now a refusal. A refusal of a bound carries the new key `limit` of `una.diagnostic/1`, `{"name","bound","seen"}`; the key is additive, and the schema stays `una.diagnostic/1`. No bound changes.
- **The order of public events where quiet code starts tasks** (#1545). In the interpreter and in native code under `--virtual-time`, a `start` under a raised program counter no longer takes a place of its statement's bound: the statement holds the task, which runs on the turn of the task that runs the statement, at that task's switches while the bound has a place free, at a quiet `start` that finds the bound full, and at the statement's end. A quiet `start` never waits. A program whose quiet code starts tasks can print its public events in another order than in 0.5.0, the same in every run and for every secret; a test that pins that order may need its expected output updated. A program whose quiet code starts no task runs as before, and native code under the real clock is unchanged.
- **`una report` entries carry `where` conditions and `gives` labels** (#864). An operation with a condition or a label is printed with them, in the human output and in `--json`; a tool that reads the entries of `authority` or `handler_authority` sees, for example, `Files[read gives internal]` where 0.5.0 printed `Files[read]`. An operation with neither prints as before, so the reports of edition `0.1` and `0.2` packages do not change. The entries stay strings, and the schema stays `una.report/2`.
- **Codes for `result`, `it` and `error` in a lambda** (#1989). A package that 0.5.0 rejected with U8001 for such a use is now rejected with U2012 or U2013, at the use. No accepted program changes.
- **One U3013 where there were two** (#837). A call with `edit` or `take` that also has effects is now one U3013, not two with different advice. The code and the first part of the message do not change.
- **The installer removes old files on an upgrade** (#1992). Run over an earlier installation, `install.sh` removes the files that the earlier installation recorded and the new one does not hold, and names them. Before anything is downloaded it checks every path of the earlier record as uninstall does, and refuses a path with a `.` or empty component, or with a directory on the way that is a symbolic link; it never removes a file that the new installation holds. The installer also writes each file as a new one after removing its name, so it never writes through a hard link (#1966), and, as root, `--uninstall` no longer refuses an unsafe TMPDIR, since it makes no work directory.

## Security

The security fixes of this release:

- **A policy call is a check point of the schedule of started tasks** (#2214). The checker did not record a policy call as a task-switch check point, so a `via` whose work depended on its argument could order the public prints of started tasks by that argument, at `secret` as at `internal`, in the interpreter under both clocks and in native code under `--virtual-time`, and the program was accepted with an empty report. Above `internal` such a call is now U4002; at `internal` it is reported as a `task switch`, the remaining channel of #1708.
- **A task that quiet code starts no longer reorders the public events of other tasks** (#1545, ADR 0117 amendment of 2026-11-22). In 0.5.0 and earlier, in the interpreter and under `--virtual-time`, a task started under a raised program counter took a place of its statement's bound, so whether it ran could make a later public `start` wait, and the order of the other tasks' public events followed `internal` data. [Known limits](../guide/known-limits.md) listed it as an open channel. The order of public events is now that of the same run without the quiet code, in both engines and for every secret. What remains is listed in the known limits: a held task that runs longer than a turn while another task is ready, or that waits itself, takes turns of its own, a count of check points that `internal` data decide (#1708).
- **A place that holds no key cannot poison the registry's root-version floor** (#2132, ADR 0122 amendment of 2026-11-19). A mirror directory, or a bundle given to `una ita unbundle`, could serve an honest root version with one added signature line of an unknown key, and `una ita fetch` stored the digest of that altered note as the floor, after which every command against the honest registry was refused as a fork (U7010). The floor now holds the digest of the root text that the root keys sign, so every form of one root text compares equal. A floor of the earlier form is still read, and is replaced once, under the floor lock, when a verified chain holds its version with exactly that note. Storing a checkpoint as the floor no longer holds the floor lock while it reads the registry, so another run no longer ends without comparing its root chain.
- **`Keys.hmac` overwrites its copies of the key** (#2120). The HMAC routine of both engines holds the padded key, its pads, the hash state and the inner digest in fixed arrays and overwrites them with zeros before it returns, where it freed heap copies of the key without a wipe. This is hardening: the wipe is not a volatile write, and the copies that the hash routine and the compiler keep are not overwritten (`docs/security/tcb.md`). Results are bit-identical.
- **The memory budget between tasks, read whole** (#2151). The bytes the process holds were derived from the allocator's limit, which changes in two writes, so a read between them could see nearly the whole address space held, and a sibling task's budget check could stop a run that was already ending with a spurious U6003 instead of its real stop. The runtime now changes the limit and reads the bytes held under its own sequence lock, so no read is torn, and a stop that ends a run claims the end of the process before it lifts the limit. No budget or ceiling changes.
- **The installer never writes through a hard link** (#1966). Each file the installer writes is written as a new one after its name is removed, so a target that is a hard link to another file, as root possibly outside `UNA_HOME`, no longer has that file written.

[Security advisories](../security/advisories.md) now holds UNA-SA-023, for the `Files` fix of 0.5.0 (#2144): a grant on the current directory was not confined against symbolic links in every release up to 0.4.0.

## Platforms

The targets are those of 0.5.0: macOS on arm64 (`aarch64-apple-darwin`) and Linux on arm64 (`aarch64-unknown-linux-gnu`) with glibc 2.39 or later. Linux on x86-64, musl systems and Windows are not targets. The glibc floor stays 2.39. What changed is the release check: it now reads the glibc symbol versions that the Linux `una` and the executables it builds ask for, and refuses an archive that needs more than the floor the installer checks (pull request #2129). [Known limits](../guide/known-limits.md) has the details.

```sh
una --version
```
