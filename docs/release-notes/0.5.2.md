# Una 0.5.2

Una 0.5.2 is the third published increment of release R0.5. It changes the edition `0.5` preview: `const` and `var` replace `let` and `let edit` there, and its modules declare constants. Editions `0.1` to `0.4` do not change, so a package of those editions needs no edit. An `Int` of any size is now written as text, and on Linux `una` runs on glibc 2.28 and later, where 0.5.1 needed 2.39. Editions `0.4` and `0.5` stay previews.

## Highlights

- **`const` and `var` in edition `0.5`** (#1628, ADR 0137). A binding that is never reassigned is written `const total = 0`, and one that is, `var total = 0`, where edition `0.4` writes `let total = 0` and `let edit total = 0`. Typing, proofs, information flow and run-time behavior are the same in both engines. A dependency of edition `0.4` keeps `let`: each package is read under its own edition.
- **Module constants in edition `0.5`** (#1632, ADR 0126). A module declares a named value at its top level, `pub const limit: Int = 4096`, with its type, and other modules import it by name. The value is a constant expression, evaluated once when the package is checked, and every reference sees the literal, so a contract that names `limit` is proven with its value. A refined constant type is proven at the value (`const port: Int in 1..65535 = 8080`). In edition `0.5`, `std.time` declares `millisecond`, `second` and `minute` as such constants. New codes: U1011 (a constant that depends on itself) and U2041 (a value that is not a constant expression, does not fit its type, or passes the caps).
- **An `Int` of any size is written as text** (#1223, ADR 0004 amendment of 2026-11-26, accepted). Interpolation, `to_text`, `to_json`, traces, outputs, failures and test reports write an integer of more than 4300 digits in full, where the run used to stop with U6003, and the conversion takes subquadratic time. The protection that the cap gave is now the memory budget: a write reserves the bytes it needs before converting, and a write that does not fit stops with U6003 at the write. Reading keeps its bound: `parse_int`, `to_int` and `parse_json` refuse more than 4300 digits.
- **Linux on glibc 2.28 and later** (#2105, ADR 0124 amendment of 2026-11-26, accepted). The Linux archive is built in an AlmaLinux 8 image with GCC 13, so `una` runs on Ubuntu 22.04, Debian 12 and AlmaLinux 8, which were tested, and on other glibc 2.28 systems by the symbol versions it needs. The installer's floor is 2.28 for this release and later; an older release keeps its floor of 2.39.
- **Clearer repairs and goals.** U3021 gives one narrowed grant per requirement, names the handler or the installation arguments that hold the excess, and keeps the other grants when one requirement cannot be met (#2213). An obligation's goal over decimals shows decimal values, `result >= 0.00`, not coefficients (#1041). `una fix` offers the rename of a reserved word only where the renamed program parses (#836). The U7013 message of `una ita verify` gives its real reason (#2209).
- **`una report` names the preview constructs a package uses** (#1752). The report's `edition` section gains `preview_constructs`, each construct of a preview edition the package uses, with its record, its number of sites and its unsettled points; the key is additive and the schema stays `una.report/2`.

## Changes that may need an edit

- **Edition `0.5`: `let` is U7007** (#1628). A package of edition `0.5` that writes `let x = e` or `let edit x = e` is now refused with U7007 at each `let`, whose repair is the exact rewrite. Migration: run `una fix` in the package, which writes `const x = e` and `var x = e`; then run `una check`. `const edit x`, `var edit x` and a `var` at a module's top level are U0101. `const` and `var` cannot name anything in edition `0.5`, and `const` is now a reserved package name in every edition. Messages of an edition `0.5` package name its words: U2019 says "declare it `var x`". Editions `0.1` to `0.4` do not change; there a line written `const x` or `var x` keeps its diagnostic and gains the help "`const` and `var` are keywords of edition 0.5".
- **Writing a long `Int` no longer stops the run** (#1223). A program whose run stopped with U6003 when it wrote an integer of more than 4300 digits now writes it, and the native executable without `--trace` behaves as `una run` does. A test that expected that U6003 needs its expected output updated. A write that does not fit the memory budget stops with U6003 at the write, where it could reach the allocator's hard limit before. The behavior added in 0.5.1 for an integer over 4300 digits at an operation without `--trace` (#1550) is replaced by this one.
- **A dependency is read under its own edition** (#1628). A package of edition `0.5` that mounts a dependency of edition `0.4` reads that dependency's files with the words of edition `0.4`. Before, every dependency was read with the root's words.

## Security

- **The tag bit of an unchecked `Int` result** (#2245, ADR 0055 NB-3, ADR 0112 EL-2). Where the range facts prove an `Int` operation in the tagged range, the native build computes it without a tag test, and now forces the tag bit of its result. If a range fact were ever wrong, the result is an `Int`, a wrong value at worst, never a word that names a heap object. This is defense in depth: no correct program's output changes.
- **Project files with `\r\n` line ends** (#2249, found by the `ita_lock` fuzz target). The reader of `ita.una`, `ita.lock`, `itaty.una`, the workspace file and `mirrors.una` gave its ranges in a text where each `\r\n` was one `\n`, so in a file with `\r\n` line ends a range after the first one named bytes to the left of what it read, and could start inside a multi-byte character. Each range now names the bytes it read. Names, versions and digests were read correctly before and after.
- **The installer refuses an unsafe target before writing** (#2216). A directory, a FIFO or a symbolic link to a directory where the installer writes a file, or a file where it writes in a directory, is refused before anything is written, where an ordinary user's installation could stop halfway.
- **The release evidence is of the shipped build** (#2254, #2181). The release gates' hunt, docs and determinism runs used a `una` that a test build had relinked with test features; they now run a saved copy of the release build, checked by its digest and refused if it holds a test hook. The `sanitize` gate runs in a clone of its own beside the build, and a failure, a crash or a missing result of it is a failure of the run.

## Platforms

The targets are those of 0.5.1: macOS on arm64 (`aarch64-apple-darwin`) and Linux on arm64 (`aarch64-unknown-linux-gnu`), now with glibc 2.28 or later. Linux on x86-64, musl systems and Windows are not targets. On Linux, `una` loads glibc's own libraries, which before glibc 2.34 include `libpthread.so.0` and `libdl.so.2`, and `libgcc_s.so.1`; its C++ runtime stays linked into it. The release check refuses an archive whose `una`, or an executable it builds, asks for a glibc symbol version above 2.28. [Known limits](../guide/known-limits.md) has the details.
