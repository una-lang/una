# Una 0.5.0

Una 0.5.0 is the first published increment of release R0.5, a release of security fixes and hardening, one of them for a fault in every earlier release: a `Files` grant on the current directory was not confined against symbolic links. The language and its editions are those of 0.4.0, and so are the targets: a program that 0.4.0 accepts needs no edit. A few answers at the edges of `Files` and of `una lsp` change, as listed below. Its number is the number of its increment: from this release, each daily increment R0.5.k publishes `v0.5.k` (ADR 0139, amendment of 2026-11-20). Edition `0.5` stays a preview.

## Highlights

This release adds no language feature. What a user gains is the fixes and the hardening under [Security](#security), and release notes like these for every release from now on.

## Changes that may need an edit

No program needs an edit: edition `0.4` stays a preview, and this release changes no construct of it. These behaviors at the edges change:

- **`Files`: a path under a missing directory.** A read or a write of a path whose intermediate directory does not exist fails with `NotFound`, decided by the confinement of the grant, and the operating system is given no path. The value was already `NotFound` in the ordinary case; it was `Io` where the path as written passed a limit of the host (more links than one lookup follows, or a path longer than the host takes).
- **`Files`: links under a grant on the current directory.** Under a grant written as `.` (or `./`, or a path that comes back to its base, such as `data/..`), a path through a symbolic link that leaves the granted directory is now `Denied`, as it always was under a grant on a named directory. So is a path whose final component is a symbolic link, wherever the link points, and a link that names nothing or loops. Earlier releases opened such paths as written.
- **`Files` grants that go up two or more levels.** A grant path such as `../../data` named `data` under the current directory in earlier releases. It now names the directory two levels up, as written.
- **`una lsp` ends with exit code 2 on input it refuses.** A frame whose header is out of bounds, or whose body is not JSON, ended the session silently with exit code 0. It now writes one line to standard error, sends a `window/showMessage`, and ends with exit code 2. A frame with more than 131,072 values, or nested deeper than 127, is dropped with the same report, and the session goes on.
- **`install.sh --uninstall` removes the proof cache key.** It removes `~/.una/proof-cache.key`, which `una` makes at run time, and then `~/.una` when it is empty; it says what it removed and names what it left. A key file that `UNA_PROOF_KEY` names is kept.

## Security

The security fixes of this release:

- **A `Files` grant on the current directory is confined against symbolic links** (#2144). In every release up to 0.4.0, under a grant on the current directory, a `Files` path was opened as the program wrote it, so a symbolic link in that directory was followed out of the grant, for reads and for writes. A path with `..` or an absolute path was refused as always. Such paths are now `Denied`. Until you update, run the package by an absolute path, or grant a named directory.
- **The language server bounds what it reads** (#1476). `una lsp` accepted a header line, a number of header lines and a `Content-Length` of any size, so a peer on its input could make it hold memory without limit. A header line now holds at most 4 KiB, a frame at most 16 header lines, and a body at most 64 MiB. Editors are not affected.
- **Requirement name suggestions** (#1474). The U1005 suggestion for a requirement identifier could overflow a number and took quadratic time on a run of taken names. It now finds a free name in O(n log n).
- **The registry root floor** (#1970). A root-version floor written as the version alone now records the digest of that version's root metadata, so `una check` refuses a forked root of that version with U7010.

- **`Files` gives the operating system no path it did not resolve** (#1459). Under a missing directory, the path as the program wrote it used to reach the operating system, where it failed. It no longer does.
- **Constant-time comparison of `Hashed` values and key hygiene** (#1481). `==` on two `Hashed` values reads every byte of both in each engine, the last step of Poly1305 has its barrier, HKDF wipes its scratch block on every path, and `Keys.hmac` no longer copies the key out of the run's table.
- **Less `unsafe` code in the runtime's system layer** (#1483). Six `unsafe` blocks became safe code, and a test now enforces the size cap of that layer.
- **The memory budget between tasks** (#1943). A step that the budget refuses is no longer visible to the steps of sibling tasks, so a task that fits its budget is not refused for another task's request.
- **The registry root floor, two runs at once** (#2099). A run that finds another digest held for its root version now fails with U7010, where it ended with a note.
- **The language server bounds what a frame becomes** (#2100). A body within the 64 MiB cap could grow to gigabytes of values when parsed. A frame now holds at most 131,072 values, nested at most 127 deep.

[Security advisories](../security/advisories.md) now holds UNA-SA-020, UNA-SA-021 and UNA-SA-022, published after 0.4.0. All three are fixed in 0.4.0, and so in this release.

## Platforms

The targets are those of 0.4.0: macOS on arm64 (`aarch64-apple-darwin`) and Linux on arm64 (`aarch64-unknown-linux-gnu`) with glibc 2.39 or later. Linux on x86-64, musl systems and Windows are not targets. [Known limits](../guide/known-limits.md) has the details.
