# Known limits

This page lists what this release of Una does not do, or does only with limits, for a user who writes programs of edition `0.4`. Each item names the rule or record that states it; the [specification](../spec/) is normative, and this page only points to it.

## Edition 0.4 is a preview

Edition `0.4` is named in `ita.una`, and it is a preview under the terms of ADR 0121 until a release declares it stable ([`spec/13 §7`](../spec/13-diagnostics-and-abi.md)). While it is a preview, a later release may, in a package of edition `0.4`, accept a construct that earlier releases reject, add obligations, errors and keywords, and change or remove a construct of the edition ([ADR 0121](../adr/0121-the-terms-of-a-preview-edition.md) rule 3). A program that one release accepts gives the same result in a later release, or is rejected with a diagnostic, except for a fix of a soundness or security error and a change at a point that the construct's record declares unsettled (ADR 0121 rule 4). Each release that changes edition `0.4` lists those changes in its changelog under the heading "Edition `0.4` preview: changes that may need edits" (ADR 0121 rule 6).

## Servers

These limits are those of [`spec/31`](../spec/31-http-servers.md), HTTP servers through the capability `HttpServer`.

- **Scripted connections.** `una run` and executables take `--serve-script` and `--serve-out`, but a script that is read and checked ends the run with the usage error "the scripted connections of `--serve-script` do not run in this release yet". Only the toolchain's own test builds serve a script (`spec/31 §8` rule 6).
- **`https` grants.** The TLS server, and the check that the key matches the certificate, wait for the decision on the project's TLS provider (#1059). Until then a run with an `https` grant loads and checks its key and certificate files and binds, and nothing accepts on any listener (`spec/31 §2` rule 8).
- **`within` in a server.** The label `L_srv` of the serve threads joins the timing label of every `within`, `first of` and `for ever within` of a package that performs an operation of `HttpServer`. Under the preview it is computed coarsely: in a server of the language form, and in a package with a `serve` section, `L_srv` is the top label, and so is every timing site of the package (`spec/31 §1` rule 5 item 7, `§7` rule 3 item 6). So a `start ... within` in the block of a `tasks` statement, whose expression performs an operation that accepts `internal`, is refused, and a server starts its request tasks without `within`; the grant's `answer` deadline bounds what each peer waits (`spec/31 §1` rule 5 item 8). Every `within` of a `serve` section is U4003 (`spec/31 §7` rule 3 item 7). The specification lets this label become more precise in a later release, and not stricter (`spec/31 §1` rule 5 item 7).
- **No share per peer for three limits.** A grant's `waiting`, `/once` and `delivered` have no share per peer: at the defaults, about 16 well-behaved addresses can fill `waiting` ([ADR 0123](../adr/0123-http-servers.md), amendment of 2026-11-02, decisions of the implementation, item 5; `spec/31 §2` rule 2). A request read in full when `waiting` is full is answered `503` with `Retry-After: 1` (`spec/31 §6` rule 5). The limits that do have shares make an exhaustion cost many addresses, not one, and do not remove it; an operator facing it raises the grant's limits or puts a filter in front (ADR 0123 rule 7).

## Tasks and timing

These limits are those of [`spec/26`](../spec/26-long-running-programs.md) and [`spec/27`](../spec/27-tasks-and-time.md). The guide [Tasks and time](tasks-and-time.md) teaches the constructs they concern.

- **Only `Http` operations are interrupted.** In this edition the interruptible operations are those of `Http`: a request waits no longer than the earliest deadline that covers it and fails with `HttpError.TimedOut` (`spec/27 §5` rule 6). Other code inside `e within d` is cancelled at its next check point, after an operation in progress completes (`spec/27 §5` rule 5). What a request sent before its deadline passed stays sent, so an interrupted request is an effect in doubt (`spec/27 §5` rule 6).
- **The residue label `L_res`.** In a program whose started tasks or races make requests, every `within` is at least `internal` (`spec/27 §5` rule 8). The failure of a `within` carries that label, and `if error pass` and `if error fail` on it are U4002 when it is above `public` (`spec/27 §5` rule 8). `L_res` also joins the label of every `first of`, every `for ever within`, every tick, the limits of grants and the statement an installation of `limiter` scopes over (`spec/26 §7` rule 5, item 6). A program pays for it only when its started tasks or its races make requests (`spec/26 §7` rule 5, item 6).
- **Code the checker does not see.** `L_res` is the top label when the package's code can reach a function of a standard module whose body holds a `tasks` statement or a `first of`, or a function of a dependency whose code the checker does not see, until issue #1166 makes these precise (`spec/26 §7` rule 5, item 6).
- **Coarse labels of concurrent work.** The statement a `limiter` scopes over and `L_srv` keep the preview's `τ_conc`: the top label for a site inside a lambda, a task, the block of a `tasks` statement or a handler's operation, in a function that a part of a task construct can reach, and, in a package with a task construct, in a function that a function value, a lambda or a handler's operation can run (`spec/27 §11`).
- **Grants with limits.** When a grant of `run grants` carries limits, `una check` reports U4001 at each `Http` site whose own label is above `internal`, and `una run` and the executable refuse a `--grant` with limits when the label of the program's requests is above `internal`, a usage error, exit code 2, before `main` starts (`spec/27 §9` rule 5). In a run where a grant carries limits, a request never parks on the reactor: it runs on a helper of the I/O pool and holds its slots until the helper returns (`spec/27 §9` rule 3).
- **Quiet tasks and the bound.** A task started in quiet code counts against the bound of its `tasks` statement, so whether a `start` under a raised program counter ran can make a later public `start` wait: an open channel (#1545, `spec/27 §7` rule 4).
- **`Json` holds only `public` data.** The positions of `Json` are unlabeled, so `public`, and a labeled value given to a `Json` constructor is U4001. A labeled text reaches JSON through a policy, or through `quote_json` and interpolation ([`spec/23 §5`](../spec/23-json.md) rule 2, #917).
- **`Clock` readings are not labeled.** `Clock.now()` returns an `Int` of milliseconds with no label ([`spec/14 §3`](../spec/14-standard-library.md)), so a program with a `clock` grant can turn elapsed time into a public value. Labels on `Clock` readings are the subject of issue #898 ([ADR 0116](../adr/0116-long-running-programs.md), Context).

## Editions

- **Collections and numerics are edition 0.5.** The collections of [`spec/28`](../spec/28-collections.md) and the numeric foundation of [`spec/29`](../spec/29-numerics.md) §16 to §19 are not part of edition `0.4`: they exist only in packages of edition `0.5` ([ADR 0139](../adr/0139-edition-numbering-follows-the-release-that-closes-it.md) rules 6 and 7, `spec/13 §7`). In a package of edition `0.4` each of them gets what edition `0.3` gives it, such as U1001 for `import std.collections` (`spec/13 §7`). `F64` and `spec/29` §1 to §15 stay in edition `0.3` (`spec/13 §7`).
- **Edition 0.5 is a preview too.** Edition `0.5` is a preview under the terms of ADR 0121 until the rules that target it have landed (`spec/13 §7`).

## Platforms

- **macOS on arm64 only.** The installer has releases for macOS on arm64; on Linux it stops with "Linux is not available in this release yet" (the Linux build of the solver that `una` carries is not yet pinned to a reproducible digest, and `una build` does not yet link Linux executables itself); on any other platform it stops with "no Una release for" the platform (`install.sh`).
- **0.4.0 and later.** The installer refuses a `UNA_VERSION` before 0.4.0: such a release needs a separate Z3, which the installer no longer installs (`install.sh`).
- **`una build` and `cc`.** On macOS arm64, `una build` links with the linker built into `una` and runs no other program (ADR 0124 step 3). A `una` for any other platform links through a C compiler as `cc`, and on Linux against the system's C library ([Getting started](getting-started.md), section 6).
- **Not as root.** The solver refuses to run as root, whose privileges no confinement removes: `una check` run as root fails with U5003, "the solver could not be confined: the solver must not run as root" (ADR 0124 rule 7). Run `una` as an ordinary user, in a container too (`docker run --user 1000:1000 ...`).
- **Foreign code inside `una`.** The `una` binary holds code not written in Rust: the Z3 solver, a C++ library (ADR 0124), which uses the system's C++ runtime (`/usr/lib/libc++.1.dylib` on macOS), and the C and assembly of `ring`, the cryptography of the default TLS provider (ADR 0133 rule 17), which the runtime that `una build` links holds too. The [foreign code inventory](../foreign-code-inventory.md) lists each item, where it reaches and its plan.
