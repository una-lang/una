# v0.1 closure plan

Status: the plan of the v0.1 closure run, started 2026-09-30 on `dev/v0.1` at `8c47819`.

Sources:
- the owner's closure prompt and its addendum of 2026-09-30;
- the independent review in `docs/reviews/v0.1-review/`, merged at `4ac7a6e`;
- ADR 0038 (Accepted, Deciders: Leonardo);
- the owner's answers in `docs/reviews/v0.1-review/escalations.md`, "Leonardo's answers".

Where `findings.md` and ADR 0038 disagree, ADR 0038 wins. A case ADR 0038 does not cover becomes a Proposed ADR and an open question, not an improvised rule.

## 1. Order of work

1. Setup:
   - merge `review/v0.1` (which makes `main` an ancestor of `dev/v0.1`);
   - record the escalation answers;
   - commit ADR 0038;
   - write this plan.
2. The spec edits of ADR 0038 (`cf9a0a5`). The registry rows U1009 and U3016 (`spec/13 §4`) and the out-of-model entry for path races (`spec/13 §6`) land with their implementations, because tests pin the registry and the report.
3. The 11 Criticals, in three tracks. Each track first turns its adversarial programs into failing conformance cases, then fixes them. The tracks are merged one at a time, with the full suite green after each merge:
   - (a) R-001 to R-006: function types, generics, labels and handlers;
   - (b) R-007 to R-010: the verifier and names;
   - (c) R-011: file grants.
4. The Majors (R-012 to R-022, except R-013 and R-022, which have their own steps).
5. F-0001-02 (ADR 0037), which also closes R-013. Then fix request 0001 is closed.
6. R-022, the neutrality rename.
7. The Minors and Notes, and the new Minor from the benchmark.
8. Decisions and ADRs (§5):
   - update the decision log;
   - remove the `DECISION D-NNN` tags of the final decisions.
9. Promote every adversarial program into `tests/conformance/` with its correct expectation, then re-verify (§7).
10. Release preparation (§8), then the pull request.

## 6. Adversarial programs

All 143 programs in `docs/reviews/v0.1-review/adversarial/` are promoted into `tests/conformance/<area>/`:
- `auth-*` go to `authority`;
- `flow-*` go to `security`;
- `verify-*` and `escape-*` go to `verification` or `authority`;
- `runtime-*` go to `runtime`.

Each case has the correct expectation, which is the reviewer's "Expected" column unless ADR 0038 decides otherwise. Its `-- test:` line names the finding (`R-NNN`), or `review control` for a program that already behaved correctly. Programs that need a setup the runner cannot do, such as a symbolic link, a forged cache file or a memory limit, become CLI tests in `crates/una-cli/tests/` instead.
