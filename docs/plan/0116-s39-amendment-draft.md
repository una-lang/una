# ADR 0116 amendment draft: the `stop` event under a raised program counter (S-39)

Status: Proposed (draft for the project's decision; it is appended to docs/adr/0116-long-running-programs.md only once accepted). Security fix of #1507; the behaviour is already implemented in the pull request.

## Amendment (2026-11-03): the `stop` event under a raised program counter (S-39)

Rule 14 appends `{"seq": n, "outcome": {"kind": "stop"}}` for every `for ever` that a host stop ends at an iteration start, with no label, and IF4 lets a `for ever` stand under any program counter. An adversarial review of #1478 (issue #1507, S-39) showed that the event leaks: whether a loop under a `secret` branch is entered, and whether its budget or a host stop ends it rather than `stop when`, depends on the secret, and so do the number of `stop` events and the `seq` of every later event. A program that calls such a loop, guarded by `s > i`, for sixteen values of `i` gives exactly `s` events, with the same output and exit status. The same holds after SIGTERM and `--deadline`, since the request is sticky, in both engines and before the per-loop budget of #1478.

The event is a sink that accepts `public`, as `Console.print` is. A `for ever` that stands under a program counter above `public`, joined with the effect floor and the timing floor as an effect's is, or that runs inside a call of a function that says `diverges` standing under one, its callees and the tasks they start included, is quiet: its stop appends no event and takes no `seq`. Elaboration marks the loop or the call `quiet` in Core, and both engines count the `quiet` expressions a task is in, a started task beginning with the count of its `start`. `spec/26 §6` rule 4 states the rule, and `spec/09 §2` the Core form.

Choice. The other sound option makes a `for ever`, and a call of a function that says `diverges`, under a raised program counter an error, as an effect is (U4002). It rejects programs whose loops perform no effect, and a server's started tasks under an `internal` program counter, which IF4 accepts; the quiet event keeps them accepted and closes the channel. Labeling the event and numbering `seq` per level would change the trace's format, `una.run/1`, for no reader that exists: the trace is one document, read by `una run --json`, `--trace`, the equivalence tests and the hunt's oracle, so the public view is the only one, and leaving the event out is the labeled event filtered for it.

Costs. Two runtime calls per entry of a quiet loop or call, O(1) each, and nothing elsewhere: code without a `for ever` or a call of a `diverges` function under a raised program counter is compiled as before.

Out of scope, unchanged: the `timeout` event of a `within` or a `for ever within` whose deadline cuts code that depends on a secret is timing, which the report's `timing` list names (`spec/27 §5`); the `aborted` event of a started task that runs too deep is stack exhaustion, and the `cancelled` events and U6007 of the hard stop are the time of a host stop, both out of model (`spec/07 §1`). The formal model has no `stop` event yet, so a declaration that runs a `for ever` is not re-checked by it.
