# U2019: Assignment to a binding that is not editable

The code assigns to a binding that is not editable.

## Why Una rejects it

Only a binding declared `let edit`, or a parameter declared `edit`, can be assigned, have a field assigned, or be passed as `edit` (`spec/17 §2`). A plain `let` and a plain or `take` parameter are fixed. In edition `0.5` the binding words are `const` and `var` (ADR 0137): a `var` binding is editable and a `const` binding is fixed, and the message says "declare it `var x`".

A lambda captures the value a binding has when the lambda is created. So inside a lambda a captured binding is not editable either (`spec/17 §5` rule 4).

## How to fix it

- Declare the binding `let edit`.
- Or bind the new value to a new name.

## Failing example

`una.toml`

```toml
[package]
name = "demo"
version = "0.1.0"
edition = "0.2"
```

`src/demo.una`

```una
module demo

pub total(xs: List[Int]) -> Int
=
  let sum = 0
  sum = xs.sum
  sum
```

## Fixed example

`una.toml`

```toml
[package]
name = "demo"
version = "0.1.0"
edition = "0.2"
```

`src/demo.una`

```una
module demo

pub total(xs: List[Int]) -> Int
=
  let edit sum = 0
  sum = xs.sum
  sum
```
