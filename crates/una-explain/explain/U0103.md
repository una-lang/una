# U0103: Reserved keyword not available in the package's edition

A reserved word is used as a keyword or as a name. The message names the planned area, "reserved for a later edition (laws)" for example, or the Una construct to use instead.

## Why Una rejects it

Some words are reserved for features planned in later versions of Una, and others name constructs from other languages that Una expresses differently. Using one as a keyword or as a name is rejected (`spec/01 §5`). For example, Una has no `return`: the last expression of a body is its result.

In edition 0.3 the test declaration is written `test` (ADR 0105), so `example` at the start of a declaration is U0103 there, "`example` is written `test` in edition 0.3". The declaration's body is read as a test's, and editions 0.1 and 0.2 keep `example`.

## How to fix it

- A word reserved for a later version, such as `table` or `all`, comes with a repair that renames it, the same way at every occurrence in every module of the package, the names an `import` line lists included: `the_table`, or `Table` where a kind or capability name is expected, with a number added when any module of the package already has that name (`the_table_2`). So applying every edit never makes a name refer to another declaration.
- In a module path the repair is advice, since the module's file must move too.
- Where the word stands as the keyword of its later construct, as `edit` in `let edit total = 0` of edition 0.1, no rename keeps the program's meaning, so there is no repair: write the program without the construct, or move the package to the edition that has it.
- In edition 0.3, `example` at the start of a declaration comes with the exact rewrite of the keyword that `una fix` applies.

## Failing example

```una
module demo

pub double(x: Int) -> Int = return x * 2
```

## Fixed example

```una
module demo

pub double(x: Int) -> Int = x * 2
```
