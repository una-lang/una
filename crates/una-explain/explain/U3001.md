# U3001: Capability not in scope

A capability operation `@c.op(...)` acts through the binding `@c` of the current capability context: a `uses` clause of the header, a `with` binding of the statement, a `given` line of an example, or the `uses` of the function type a lambda is written for (`spec/05 §1, §3`). U3001 reports a reference that no binding in scope holds. It also reports a call whose callee needs `@x: C[ops]` when the caller holds no `@x`, or holds a capability other than `C` under that name (`spec/05 §4`), a `do` line that needs a capability no `given` line binds (`spec/08 §2`), and a private function whose inferred reference cannot be given one capability, because no caller binds it or callers bind it to different capabilities (`spec/04 §5`). Bind it with `with` from a binding in scope, or install a handler with `given`, which keep the code's authority; declaring the capability with `uses` widens the header, and its repair says so (ADR 0097).

## Failing example

```una
module demo

capability Log
  op write(line: Text) -> Unit

pub note(line: Text) -> Unit
  uses @journal: Log[write]
=
  @log.write(line)
```

## Fixed example

```una
module demo

capability Log
  op write(line: Text) -> Unit

pub note(line: Text) -> Unit
  uses @log: Log[write]
=
  @log.write(line)
```
