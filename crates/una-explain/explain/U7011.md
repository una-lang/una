# U7011: A locked package that is neither in the vendor directory nor in Itaoca

A package of edition `0.4` builds from what its lock pins, with no network (ADR 0122, `spec/30`). Every command that loads the package looks for each locked registry package in the vendor directory of the root, `vendor/ita/<source>/`, and then in Itaoca, the store of fetched packages under `~/.una/itaoca` or the directory `UNA_ITAOCA` names. No command but `una ita` ever reads a registry. U7011 reports a locked package that is in neither place, or whose provenance at the lock's resolution point Itaoca does not hold; the need is not mounted, so the package's modules cannot import it. The repair is `una ita fetch`, which reads the release from the first of the source's places whose copy verifies, the mirrors Itaoca's `mirrors.una` lists then its own URL, verifies it and stores it in Itaoca, then, to build anywhere with `una` alone, `una ita vendor`, which copies it with its provenance into the vendor directory to commit with the lock. A self-contained example cannot carry a registry's signed files, so the fixed example shows the package once the dependency is no longer needed.

`ita.una`

```una
ita demo
  version 0.1.0
  edition 0.4

sources
  acme "https://ita.acme.example"
    root "sha256:5e0d1b7a5e0d1b7a5e0d1b7a5e0d1b7a5e0d1b7a5e0d1b7a5e0d1b7a5e0d1b7a"
    owners acme

needs
  acme/ledger 0.3 from acme
```
