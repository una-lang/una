# U3029: a failure that must be handled where it is not

In edition 0.4, the host drives a package that names a module in `[drive]`: it calls `init` once, then `step` once per tick, then `on_stop` when the program stops (`spec/26 §2`, ADR 0116 rule 2). The host has no caller to give a failure of `step` or `on_stop` to, so neither may declare `fails`: each failure they meet is handled inside them, with `if error use` or `attempt`. `init` may fail, and its failure ends the run as a failure of `main` does (U6001). The error is at the `fails` clause.

## Failing example

`una.toml`

```toml
[package]
name = "demo"
version = "0.1.0"
edition = "0.4"

[drive]
module = "demo"
ticks = 1000
```

`src/demo.una`

```una
module demo

import std.drive (Tick)

pub kind Fail = Bad

pub init() -> Int = 0

pub step(edit count: Int, input: Tick) -> Unit
  fails Fail
=
  count = count + 1
```

## Fixed example

```toml
[package]
name = "demo"

edition = "0.4"

[drive]
```
