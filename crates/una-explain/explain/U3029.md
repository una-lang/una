# U3029: a failure that must be handled where it is not

In edition 0.4, the host drives a package whose `ita.una` names a module in its `drive` section: it calls `init` once, then `step` once per tick, then `on_stop` when the program stops (`spec/26 §2`, ADR 0116 rule 2). The host has no caller to give a failure of `step` or `on_stop` to, so neither may declare `fails`: each failure they meet is handled inside them, with `if error use` or `attempt`. `init` may fail, and its failure ends the run as a failure of `main` does (U6001). The error is at the `fails` clause.

## Failing example

`ita.una`

```una
ita demo
  version 0.1.0
  edition 0.4

drive
  module demo
  ticks 1000
```

`ita.lock`

```una
lock 1

solver
  encoding "una-smt-1"
  name "z3"
  version "5.1.0"
  logic "QF_UFLIA"
  steps 5000000
  seed 0
```

`src/demo.una`

```una
module demo

import std.drive (Tick)

pub kind Fail = | Bad

pub init() -> Int = 0

pub step(edit count: Int, input: Tick) -> Unit
  fails Fail
=
  count = count + 1
```
