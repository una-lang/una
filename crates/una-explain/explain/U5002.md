# U5002: Obligation unknown

The solver could not decide a proof obligation within the `step_budget` of `verification.lock` or the wall-clock guard of `--solver-wallclock`. In v0.1 an unknown obligation is an error, as a refuted one is (ADR 0008): nothing the solver could not prove is accepted. The message gives the solver's reason. Simplify the goal, give the proof the hypotheses it needs through stronger types or `requires` clauses, or raise the step budget; the proof is still required, so a raised budget keeps the guarantee. The repairs are those of U5001, and `checked` is the last one, marked as an escape (ADR 0095).

A loop has a reason of its own: "the loop forgets every fact about ...". A loop keeps only the refinements of the bindings it updates, so a postcondition about what it built, as `result.len <= votes.len` or `counts.has(key: v)` after the loop, stays unknown however the solver is given time. Put the fact on a helper that does one iteration's update to an `edit` parameter, whose `ensures` names the parameter's value on entry as `old(p)`, as `counts.has(key: vote)` or `counts.len <= old(counts).len + 1`: the solver proves it once, and each call gives it to the caller right after the call. The loop's own postcondition about everything it built still cannot be proven; state what the callers need on the helper (`spec/17 §5`, the guide for agents, §11).

Floating point has reasons of its own (edition `0.3`, `spec/29 §8`). A query with an `F64` term runs with the fixed step budget 5,000,000 whatever the lock sets, so raising `step_budget` does not decide it, and a query whose float arithmetic weighs more than 4 (a multiplication, a division, a square root or a conversion weighs 4, an addition or a subtraction 1) is not sent at all. Move the fact to a checked boundary (`checked(value, p(it))`, an escape), split the contract so that each helper's `ensures` states a fact about one operation, or state a weaker property, such as finiteness, a sign or a bound by a constant. A refutation that holds unless floating-point facts make its path unreachable is unknown too, and so is a fact that needs `n.to_f64()` of an `Int` outside -2^63..2^63, which the verifier does not interpret: give `n` a range refinement or a fixed-width type.

## Failing example

`verification.lock`

```toml
encoding_version = "una-smt-1"
solver           = "z3"
solver_version   = "5.1.0"
logic            = "QF_UFLIA"
step_budget      = 1
random_seed      = 0
```

`src/demo.una`

```una
module demo

pub kind Seats = Int in 0..5000

pub shift(seats: Seats, by: Int) -> Int
  ensures result >= by
=
  seats + by
```
