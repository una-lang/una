# U7010: A package, archive, statement, root, checkpoint or log proof that fails verification

A package of edition `0.4` is pinned by `ita.lock` to the content digest of each package it uses (ADR 0122, `spec/30`). Every command that loads the package verifies, offline, each locked registry package it reads from the vendor directory or from Itaoca: its files are read with no symbolic link followed, only regular files and directories, and only the paths a package may hold; the digest of the bytes read must be the lock's; and the provenance stored beside it must verify against the lock: the source's root metadata from the pin in `ita.una`, the checkpoint of the lock's resolution point with its log signature and its witnesses' cosignatures, and the release statement, its digest, its signature by the key the lock names, and its inclusion in that checkpoint. U7010 reports what failed and where it came from: a vendored or stored package that was changed after it was fetched, a file a package may not hold, an archive that does not read, or a provenance that does not verify. A vendored package that fails is not replaced by the copy in Itaoca. There is no mechanical repair: a failure is evidence that the files were changed, or of an attack. Find out why, then remove the copy and vendor or fetch it again.
