# U6006: The floating-point environment of the platform is not the default one

A self-test finds that the floating-point environment of the platform is not the default one. When a probe gives other bits, the run stops before the program starts, with U6006 and the name of the probe, exit code 1 and no source location.

## Why Una rejects it

Every `F64` result is the same, bit for bit, in both engines and on every machine (`spec/29`, ADR 0114). That holds only under the default floating-point environment: rounding to nearest, ties to even, with subnormal numbers neither flushed to zero nor read as zero.

- A native executable of edition `0.3` or later writes that environment when it starts and on each of its threads, and then runs a self-test whose probes tell each other rounding mode and each flush mode apart.
- `una run`, `una test`, `una check`, `una build` and `una core` run the same self-test on a package of edition `0.3` or later before they read its sources, since they convert float literals.
- The language server runs it when it opens such a package.
- Packages of editions `0.1` and `0.2` never run the self-test.

## How to fix it

The cause is the platform, not the program, so there is no failing example to show here: an emulator setting, a preloaded library or other foreign code left a mode the language cannot run under as specified. Run on a supported platform, and remove what changes the environment.
