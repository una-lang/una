# U7016: A message of the editor that `una lsp` refuses: past a bound of its transport, not framed or not JSON

U7016 reports a message that an editor sent to `una lsp`, the language server, and that the server refused. The server writes the diagnostic on standard error, one line per refusal, as `error[U7016]: <message>`, or with `--json` as one `una.diagnostic/1` document per line, and shows the same code and text to the editor in a `window/showMessage` notification of type error. The message names the bound a refusal passed; the JSON form also has the key `limit`, with the bound's name, its value and the value seen.

## Why Una rejects it

The language server does not trust its peer with memory (`spec/13 §5`, `docs/compiler/architecture.md`). Every frame has fixed bounds, checked before anything of their size is held:

- `MAX_HEADER_LINE`: a header line holds at most 4096 bytes, its line ending not counted.
- `MAX_HEADER_LINES`: a frame has at most 16 header lines.
- `MAX_CONTENT_LENGTH`: a body holds at most 67,108,864 bytes (64 MiB).
- `MAX_DEPTH`: a body nests at most 127 arrays and objects.
- `MAX_VALUES`: a body has at most 131,072 values, its own value, each element and each member.

A body past `MAX_DEPTH` or `MAX_VALUES` was read whole, so the next message starts where it should: the server drops the message, and the session goes on. A request in a dropped message gets no response, and the session exits with code 1 when it ends. Every other refusal leaves no known start for the next message: a header past a bound, a header line that is not UTF-8, a `Content-Length` that is missing or not a number, a body that is not JSON, or a header or a body cut short by the end of the input. The server then cancels its checks, reads no further and exits with code 1.

`una check` never reports U7016, since it comes from the bytes an editor sends, not from a program's text, so this text has no example.

## How to fix it

The cause is the editor or its extension, not the program. A body that is not JSON usually means a wrong `Content-Length`; a message past a bound means a client that sends more than LSP needs, since a client's `initialize` has a few thousand values. Update or fix the client. The bounds are fixed: no flag raises them.
