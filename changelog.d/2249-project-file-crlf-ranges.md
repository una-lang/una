- **The ranges of the project files index the text as written** (#2249, found by the `ita_lock` fuzz target): the reader of `ita.una`, `ita.lock`, `itaty.una`, the workspace file and `mirrors.una` gave its ranges in the decoded text, where each `\r\n` is one `\n`, so in a file with `\r\n` line ends a range after the first one named bytes one to the left of what it read, and could start inside a multi-byte character such as a U+FFFD that replaced an invalid byte. Each range is now mapped back to the text it was given, so a diagnostic points at the token it names; a file with `\n` alone reads as before. The formatter and `una ita add` and `remove` still read and write the decoded text, `\n` alone.
