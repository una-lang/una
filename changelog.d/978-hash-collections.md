- **`HashMap` and `HashSet` in edition `0.4`** (#978, ADR 0119 rules 8 to 12). `std.collections` exports `empty_hash_map` and `empty_hash_set`. A `HashMap[K, V]` has the built-in methods `has`, `get`, `edit set`, `edit remove`, `with`, `without`, `edit update`, `keys`, `values`, `entries` and `same_entries`, and a `HashSet[T]` has `has`, `edit add`, `edit remove`, `with`, `without`, `items`, `union`, `intersection`, `difference`, `is_subset` and `same_items`; both have `.len`. Keys and items are of any `Eq` type, records and lists included, hashed with SipHash-2-4 under a key of each table derived from a process key that the run reads from the host's random source before `main`, and only when its code can make a table; a host without random bytes aborts the run with U6009 before any effect. Tables list in insertion order, so no output or trace depends on the key, and have no `==`: `same_entries(as:)` and `same_items(as:)` compare as sets. Lookups and updates are O(|k|) expected, and updates of a table held only once happen in place. The keys and items are the table's shape for labels, `update` runs `change` under the key's label, and stored keys, values and items carry the `refinement` obligations of refined types. The interpreter runs both types; the native backend reports them as not supported yet. `spec/28 §7` states the operations, their costs and their labels.
