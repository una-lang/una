- **A slow backend no longer stalls a server under `una run`** (#1730, ADR 0117 amendment of 2026-11-09, `spec/27 §8` rule 2). In a run that serves live peers and has a `tasks` statement, the interpreter makes an `Http` request on a helper thread while its task parks, as native code does, so one request that waits on a slow or unreachable backend no longer holds the delivery of every other request until `--http-timeout`. The helpers are capped as native code caps its requests' sockets (`spec/27 §2` rule 3, usually 256 places in a run that serves): a request that finds no place free runs on the interpreter's thread, as before. A request in flight runs to its own deadline even when its task is cancelled or the run aborts or stops, so the run can wait up to `--http-timeout` (30 s by default) for one at its end, and after a host stop end with 143 at twice `--stop-grace`. These requests share the run's limits, so a throttled grant can now fail one with `RateLimited` under `una run` too. Runs without a `serve:` grant, scripted runs and runs without `tasks` keep their requests on the interpreter's thread and their schedule.
