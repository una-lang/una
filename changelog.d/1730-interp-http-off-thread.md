- **A slow backend no longer stalls a server under `una run`** (#1730, ADR 0117 amendment of 2026-11-09, `spec/27 §8` rule 2). In a run that serves live peers and has a `tasks` statement, the interpreter makes each `Http` request on a helper thread while its task parks, as native code does, so one request that waits on a slow or unreachable backend no longer holds the delivery of every other request until `--http-timeout`. The requests' sockets are capped as native code caps them (`spec/27 §2` rule 3): a request past the cap waits for a place, first come, first served, within its deadline. A cancelled task's request ends `Interrupted`, and one cut by a `within` around its `tasks` statement `TimedOut`. Runs without a `serve:` grant, scripted runs and runs without `tasks` keep their requests on the interpreter's thread and their schedule.
