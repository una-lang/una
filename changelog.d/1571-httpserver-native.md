- **The operations of `HttpServer` in native code** (#1571, ADR 0123 step 5, `spec/31 §1`), edition 0.4 preview. `next`, `reply` and `close` run in `una-rt` over the same serve engine and the same table of reply rights as the interpreter, with its checks in its order: an abort of the run, then `close`, then the host stop, then one atomic delivery; a `next` with nothing to deliver lets a ready task that can make progress run first, and otherwise waits for the engine, on the worker under virtual time and on a helper of the I/O pool while the task parks under the real clock. A `ReplyRight` is now a value of native code: `==` compares the exchange it names, and interpolation writes `<reply-right>`. `start` moves the reply rights its captures reach before the task is queued, in the interpreter's order. A task's end answers the rights it still holds, `500` or `503` with `Retry-After: 1`, each with its `unanswered` event. In a run that serves, an abort of the run by a started task lets every task stop at its next check point, and an abort of the root unwinds it through its `tasks` statements, which cancel their tasks, so the host answers each task's rights and writes its events, as in the interpreter; a `next` that resumes after an abort ends `aborted` even when a cancellation came with it, in both engines; a hard stop and an internal error still end the process at once, after the host answers every right left with `503`. The runs of `tests/serve_runs/` run natively too, through a scripted engine that only the toolchain's own test builds of the runtime compile, and must give the interpreter's bytes, output and trace.
