- **Tasks run as coroutines on a few workers** (#966, ADR 0117 rules 1 to 3, `spec/27`). In native code each task of `together` and `together for` runs on a coroutine with a guard-paged stack from a pool, pinned to one of `--workers` threads; a join parks its task instead of blocking a thread, and `Files`, a blocked `Console.print` and `Http` run on helper pools (`--file-threads`, `--io-threads`) while their task parks. A program without tasks runs as before, with no worker and no helper. The stack each task uses now counts toward `--max-memory`. New flags on executables, `una run` and `una test`: `--workers`, `--task-depth`, `--io-threads` and `--file-threads`, each a usage error (exit code 2) when it is not a number or out of range. The context switch and the stacks live in `una-sys`, behind a safe interface: a panic inside a coroutine aborts the process, and dropping a suspended coroutine aborts without running code on its stack. Soundness: a task's worker depends only on the program's structure (#1145, `spec/27 §1` rule 2). The task of index `i` of a block runs on worker `(w + i) mod N`, `w` being the worker of the task that runs the block (0 for the root), instead of the next worker of a counter shared by the whole run, which carried how many tasks earlier code had started, possibly decided by `secret` data, into the timing of a later `public` block, and a deadline around that block into a value (ADR 0116 IF6). A program that holds a task construct or a `for ever` starts every worker and both helper pools at their full sizes, and fills the stack pool with stacks of one size, before `main` (#1145, ADR 0116 amendment P8, `spec/27 §1` rule 4), so whether a thread exists is never state that earlier code left; a thread that cannot start, or a stack that cannot be mapped, stops the run there with U6003, and a program without these constructs starts no thread. Release note: an executable whose program has tasks or a `for ever` reserves, before `main`, 64 task stacks of the size `--max-depth` gives, about 21 GiB of address space at the default 10,000, of which it uses only what its tasks touch; under strict overcommit (Linux `vm.overcommit_memory=2`) the reservation can fail, and the run then stops with U6003 before `main`; a lower `--max-depth` shrinks it.
