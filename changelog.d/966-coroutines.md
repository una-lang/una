- **Tasks run as coroutines on a few workers** (#966, ADR 0117 rules 1 to 3, `spec/27`). In native code each task of `together` and `together for` runs on a coroutine with a guard-paged stack from a pool, pinned to one of `--workers` threads; a join parks its task instead of blocking a thread, and `Files`, a blocked `Console.print` and `Http` run on helper pools (`--file-threads`, `--io-threads`) while their task parks. A program without tasks runs as before, with no worker and no helper. The stack each task uses now counts toward `--max-memory`. New flags on executables, `una run` and `una test`: `--workers`, `--task-depth`, `--io-threads` and `--file-threads`, each a usage error (exit code 2) when it is not a number or out of range. The context switch and the stacks live in `una-sys`, behind a safe interface: a panic inside a coroutine aborts the process, and dropping a suspended coroutine aborts without running code on its stack.
