- **The state of a driven module is one type with labels aside, function types included** (#1644, `spec/26 §2` rule 2). The host's shape check of `una run` and `una build` compared the labels inside a function type of the state. So `init() -> fn(Int) -> Int` with `step(edit f: fn(Int) -> secret Int, ...)`, which `una check` accepts, was refused with exit code 2. It now runs in both engines; the labels are the checker's (U4001 at each hand-off, #1642). The run-time check also ignored refinements. Before U7008 (#1641) refused every refinement in the state in `una check`, `init() -> Int` with `step(edit n: Pos, ...)` ran with a state nothing proved positive: the interpreter stopped at a division by zero the verifier had discharged, and the native build, which elides that check, printed a wrong result. As defense in depth behind U7008, the run-time check now compares refinements predicate by predicate and in order at every position, and a function type's `uses` and `fails` exactly; a difference is the usage error of the shapes, exit code 2.
