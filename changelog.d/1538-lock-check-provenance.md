- **Security: `una ita lock --check` verifies each registry package's provenance against the root version it accepted** (#1538, ADR 0122, amendment of 2026-11-09; `spec/30 §4`, §9 rule 7). With and without `--fresh`, the check now verifies the provenance of each registry package of the lock, the vendored copy or else Itaoca's, as the offline load does, against the larger of the root-version floor Itaoca stores and the last root version of the chain the command walked at the lock's point, whether or not storing that floor succeeded. A vendored provenance whose later root versions were dropped, with the lock's `last root` lowered to match, used to pass `--check` wherever the floor could not be stored, such as a CI run with an empty Itaoca; it is now refused (U7010) with the repair: lock again at a fresh resolution point. A retired witness counted without its proof, or a floor that cannot be read, is U7013. A lock whose provenance predates an honest root rotation now fails `--check` the same way, as it already failed `una check` once the floor was stored. Storing floors is still a note on failure.
