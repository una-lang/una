- **One waiting `next` woken per request, and the serve threads in place before the first job** (#1571, ADR 0123, `spec/31 §6` rule 14), edition 0.4 preview: a queued request, an ended exchange and a delivery each wake one `next` waiting on the live engine instead of every one, a stop still wakes all, and a `next` that leaves at a cancellation hands its wake on, so a request costs O(1) wakes whatever the number of waiters (scaling test with 4 and 256 waiters); the serve threads report in place before the run starts (S4 design SC6).
