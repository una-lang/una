- **Limits count only the code between two requests** (#1155, ADR 0116 P11). `L_lim` is now the meet of P10's label over the ancestors' whole bodies and P11's over the code that can run between two requests of one task: `Gap` of every body over a control-flow graph of its Core IR (failure edges, the cuts of `within`, loops with their back edges, `start` and the task constructs as calls, prelude functions that apply a lambda), the driver's gaps (`τ⁰(step)`, `Suf(init) ⊔ Pre(step)`, `Pre(on_stop)`), `τ_conc` at each request and `L_res`. Work on data above `internal` before a run's first request, a handler's parameter its operations never read, and calls of lambdas whose code is known no longer refuse a limited grant (`limits_between_before_first`, `limits_between_timed_before`, `limits_lambda_handler`); work between two requests still does, and U4001 names the body whose code between requests raised it. The labels are computed in linear time; Core IR is built for them only when P10's label is above `internal`.
