- **The installer refuses what it may not replace at a target before it writes anything** (#2216, from the review of #2203): for every user, a directory, a FIFO or a symbolic link to a directory where the installer writes a file (`bin/una`, `bin/una.new`, `lib/libuna_rt.a`, `README.md`, `LICENSE`, the record, a guide), or a file where it writes in a directory (`UNA_HOME`, `bin`, `lib`, `docs`, `docs/guide`), is now refused with the installer's own one-line message: a target of every installation before anything is downloaded, the runtime and the guides, which only some archives hold, once the archive is unpacked, and in both cases before anything is written or removed. So is, for an ordinary user, an existing directory the installer writes in that the user cannot write in (such as a `docs/guide/` of mode 555). A regular file or a link at such a name is still replaced, whoever made it; a directory or a special file is never removed to make room. Before, an ordinary user's installation stopped halfway with a raw `rm` error, after the new `bin/una` was in place and with the earlier record kept. Since #1966, a `README.md`, `LICENSE` or guide that is a symbolic link to an ordinary user's own file is removed as a link and replaced by a new file, and the user's file is no longer written through. The installer's loop variable `path`, which zsh ties to `PATH`, is renamed `rel`, so that no loop of the script overwrites `PATH` when it is read by zsh in its native mode; the documented invocation stays `sh`.
