- **Security: the outer-sandbox check of the solver asks about the loopback network, local sockets and every write at fixed places** (#1363, #1364, S-31, S-32, ADR 0124 rule 7 and its amendment of 2026-11-01, `spec/13 §5`): on macOS, a solver child under an outer sandbox now takes it as its confinement only if it denies `network-outbound`, `network-inbound` and `network-bind` with no filter, toward `127.0.0.1` and `::1` over TCP and UDP and toward local sockets, and eight write operations (data, create, unlink, extended attributes, mode, flags, times, owner) at `/`, `/Users`, `/private/var`, `/private/tmp`, `/Volumes`, the account's home directory and the user's temporary directory, none taken from the working directory; before, a profile that allowed connections to `localhost`, writes under the home directory, or attribute and mode changes was accepted. An answer the library gives for an operation it does not know is U5003, never a denial. Once the outer sandbox is accepted, the child's open-file limit is zero, so no socket or file can be opened. `tcb.solver_outer_denied` names every probe. The outer-sandbox tests fail, instead of passing, under a sandbox that refuses a nested one unless `UNA_SKIP_NESTED_SANDBOX_TESTS=1` is set, and a failure to put stderr back after `sandbox_init` still reports its reason.
