- **Native calls check their limits on a fast path** (#598, ADR 0102). Every call and loop iteration of a native executable checks the call depth, the stack, the memory budget and cancellation. These checks now read a per-thread record of plain values first, and take the full path, unchanged, only when a limit might be reached or a cancellation flag is set. Every check is kept, fires at the same call or iteration, and gives the same diagnostic and exit status; the record allocates nothing, so the memory budget fires at the same byte. On the benchmark of #595, 10^7 calls in edition `0.2`, a release executable takes 1.039 s against 1.207 s, 14% less, about 17 ns per call (medians of 15 interleaved runs). The fast path is O(1) on `main`'s thread and O(k) in a task k blocks deep, one flag load per enclosing task.
