- **A solver query past its processor-time limit always ends as `cpu`** (#2268): Z3's front end handles `SIGXCPU` by printing from inside the signal handler, which is not async-signal-safe, and once in 69 runs on glibc 2.28 the solver child aborted inside `malloc` instead (an `unknown` with reason `crash`, never a proof); under load, about one run in a hundred of an allocation-heavy query deadlocked inside that handler until the wall-clock guard ended it (`wallclock`). The solver child now blocks `SIGXCPU` before its limits are set and takes the signal on a thread of its own, which ends the child by that signal with its default action, so Z3's handler never runs; the parent reports `unknown` with reason `cpu`, as the specification says (spec 12 §4). The child's system-call filter on Linux allows `rt_sigtimedwait` for that wait.
