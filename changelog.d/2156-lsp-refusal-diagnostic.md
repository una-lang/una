- **`una lsp` reports a refused message as U7016, and `spec/13 §5` says what follows** (#2156, after #2100): each message of the editor that the language server refuses is now a diagnostic with the new code U7016 (domain `project`, with its `una explain` page), located at the empty `file` at 1:1. On stderr it is one line, `error[U7016]: <message>`, or with `--json` one `una.diagnostic/1` document a line, since stdout carries the protocol; the `window/showMessage` sent to the editor carries the same code and text. A refusal of a bound has the new key `limit` of `una.diagnostic/1`, `{"name","bound","seen"}`, as `{"name":"MAX_VALUES","bound":131072,"seen":131073}` (`seen` is `null` for a `Content-Length` that does not fit in 64 bits); the key is additive and omitted otherwise, so the schema stays `una.diagnostic/1`, and the human output of any command prints it as a note. A message past `MAX_DEPTH` or `MAX_VALUES` is dropped and the session goes on; a header past a bound or not UTF-8, a missing or malformed `Content-Length`, a body that is not JSON and a body cut short end the session. Behavior that changes: a session that reported a refusal now exits with code 1, as every diagnostic with a code does (ADR 0036), where a fatal refusal exited with 2 and a dropped message with 0; a failure to read the input stays text without a code, exit code 2. The texts of the refusals name their bound (`(MAX_HEADER_LINE)`, `(MAX_HEADER_LINES)`, `(MAX_CONTENT_LENGTH)`), and a body cut short says how many of its bytes arrived. No bound changes.
