- **The release gates undo the clone's release tag** (#1017). The `release` and `reproducible` gates of `scripts/release-gates.sh` make the tag `v<version>` in their clone for `scripts/local-release.sh` and now undo it when the gate ends, however it ends (a tag the clone had from its source is put back), so a later `mac`, `linux` or `linux-arm64` run on the same `OUT`, in a run split into groups, no longer sees the version as released; a tag left by a killed run is undone before the next run's first gate. `scripts/release-gates-tag.sh` changes only the clone that the `clone` gate made under `OUT`, checked by a marker, never another repository or the remote, and `scripts/release-gates-tag-test.sh` checks it on temporary repositories. One run at a time holds an `OUT` (`OUT/release-gates.lock`, exit code 2 for a second run), `OUT` is compared by its physical path, so a spelling through a link is the same `OUT`, and the gates unset `GIT_CONFIG_PARAMETERS`, `GIT_CONFIG_COUNT` and its keys with the other git variables. An `OUT` cloned before this change needs the `clone` gate again.
