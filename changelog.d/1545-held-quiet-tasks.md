- **Security (S-40 remainder): a task that quiet code starts no longer reorders the public events of other tasks** (#1545, `spec/27 §7` rule 4, ADR 0117 amendment of 2026-11-22). In the interpreter and in native code under `--virtual-time`, a `start` under a raised program counter, at `internal` since #1684, took a slot of its statement's bound, so a later public `start` could wait for it, and quiet code that parked, at a quiet `start` at the bound or at the end of a quiet `tasks` statement, let the queued tasks run first: the order of the other tasks' public events followed the data, the same in every run. Such a task is now held by its statement: it joins no queue and counts against no bound, and the task that runs the statement runs it on its own turn, at the front of the queue with a turn count of its own: at that task's switches (the end of its turn, a park, a wait in `next`) while the bound has a place free, at a quiet `start` that finds the statement holding as many tasks as its bound, and at the statement's end. A quiet `start` never waits, and the public events keep the order of the same run without the quiet code, in both engines, for every secret; a server loop that starts a task per request under a decision on the request still answers each request before it waits for the next. What remains: a held task that runs longer than a turn while another task is ready, or that waits itself, is let go and takes turns of its own, a count of check points that `internal` data decide (#1708). Native code under the real clock is unchanged; its order across tasks is real time, out of model. The proposed separate bounds for quiet tasks are withdrawn.
