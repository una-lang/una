- **`Files` confinement makes O(c) lookups on its normal path** (#1343, `spec/14 §3`, ADR 0038 D9). `confine`, which both engines use, resolved every intermediate directory by canonicalizing the whole lexical prefix up to it, O(c²) lookups of components for a path of c components. Each directory is now resolved from the one before it, already canonical, through a new `World::step` that the worlds of `una run` and of native executables answer with one `lstat` (and a canonicalization only for a link); one canonicalization of the lexical prefix where that resolution stops confirms it, and the next one decides as before. Where the two disagree, which takes a host limit (more links in one path than the host follows, a lexical path longer than the host takes) or a name spelled in another case on a case-insensitive file system, the earlier prefix-by-prefix resolution decides, at its earlier cost of O(c²) lookups, which any path can reach; the bound of O(c) holds for paths that do not. The rules of `spec/14 §3` and every outcome (`Denied`, `NotFound`, the path opened) are unchanged: a differential test compares the earlier algorithm with the new one over every path of up to three components, links and dangling links included, on the disk and on an in-memory model, a test runs the same link cases in both engines, and a counting world holds paths of c and 10c components within 20 times as many lookups.
