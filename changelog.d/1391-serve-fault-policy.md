- **Serve engine fault policy** (#1391, ADR 0123 amendment of 2026-11-02 decision 10, `spec/31 §6` rule 13), edition 0.4 preview. A panic of the host is still contained to the connection it happens on, and the run now stops with the hard stop when a serve callback (`on_ready`, `on_slot_freed`) panics, when a panic happens with a lock of a grant's shared state held (a delivery queue, an exchange's request, a connection's pending reply, the pressure heaps, a registry shard, a peer table shard), or when the run's contained faults pass 64. After a stop nothing is accepted, a reply is discarded, and the next delivery reports the failure, whose message names the cause. Contained faults no longer print through the panic hook; the panics that stop the run or end a serve thread still do, and a callback that panicked is not called again. Three windows that left a slot or a peer's place held are closed: a fault in the peer's admission after its place was taken, a fault in the hand-off before the connection reaches its owner's inbox (or its owner's table), and a panic inside the closing of a connection, which is now resumed past the faulting step. Faults are counted per grant and for the run; `faults()` and the trace event come with S5 (#1571). No program can name `HttpServer` yet (#1007), so no released line is affected.
