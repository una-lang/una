- **Virtual time and `stop after` in tests, edition 0.4 preview** (#945, ADR 0116 rule 19, `spec/26 §8`). An example may end with `stop after N`: a host stop then arrives once `N` iterations of `for ever` loops have started, every `for ever` stops at its next iteration start with a `stop` event and runs its `on stop`, and only under that line may the `do` line call a function that says `diverges` (U3027 otherwise). Time in a test is virtual: a clock from 0 that never waits, which `std.testing.elapse(d: Int of Millisecond)`, with `requires d >= 0`, moves forward at once. `una run` and executables take `--virtual-time`, which gives the run that clock: `Clock.now` reads it, the driver's ticks jump to their due moments, so a tick a day runs at once with `missed` 0, and both engines give the same output and trace, the clock's readings included. Before edition 0.4, `stop after` does not parse and `elapse` is not in `std.testing`. The deadline of `for ever within` is measured on the run's clock in both engines, so under virtual time it passes only when the virtual clock reaches it; `--deadline` stays on the wall clock.
