- **The `site` gate audits the website's npm packages** (#783). Before `npm ci`, `scripts/site-website.sh` runs the pinned website's `scripts/deps-audit.mjs`: `npm audit` of its `package-lock.json` against the npm registry, with npm at the version the website pins, failing on any advisory, on an audit that does not answer, offline included, and on one that did not count every package. The website's tests, which its build runs, check the lockfile against its supply-chain review record, every package by path, version, license and integrity hash, from the registry only, with licenses from an allowlist: permissive ones, and LGPL-3.0-or-later only for the build-time image tool `sharp` and its `@img` packages. `site/website.lock` moves to the website commit that adds both.
