- **Inferred operation labels, locked labels and `gives` in `una contract`** (#1396, part 2 of #566, ADR 0094 rule 3 and ADR 0092 rule 8). In edition `0.3`, a private function without `uses` clauses now infers the labels of its operations: each reads at the join of the labels its callers' bindings give it, through `with @x = @y` and `with @x = @y[ops]`, so passing a labeled binding to it is no longer refused with U3022, and its body reads the answers at that label (a `public` return of such an answer is U4001, a branch on it raises the program counter). A private function with a declared header that lists the operation without `gives` still gets U3022, and a function whose inferred `uses` label an operation is not a function value (U3006). A `[contracts]` lock may now write `gives` and a label after a locked operation, instead of being refused with U7002: the header must read the operation at the lock's label or above, else U3023 at the operation, whose first repair raises the header's label to the join and which `una fix` applies; a category the package does not declare is U7002 at the entry. `una contract` prints an inferred header's labels, and `una.contract/1` gains `gives` in each `uses` entry that labels an operation, left out otherwise, so documents of editions `0.1` and `0.2` do not change. `spec/05 §3`, `§9` and `spec/13 §5`, `§7` state the rules.
