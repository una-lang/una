- **A FIFO, a device or a directory at `ita.lock` is refused, a growing path-dependency manifest gets the bound's message, and every open of a project file is non-blocking and takes no terminal where the platform allows** (#2348, #2349, #2350, `spec/30 §1` rule 4; kind: U7008, U7009). `una check` and `una ita verify` said "the package has no ita.lock" when `ita.lock` was a FIFO, a device or a directory; they now refuse it as not a regular file, and a link that names nothing is still no lock. A path dependency's `ita.una` that grew while it was read was refused as having "changed while it was read"; it is now read through the same capped read as the root's files and refused as holding more than its bound. The opens of `tree` now add `O_NOCTTY` beside `O_NONBLOCK`, and both are known on macOS, on Linux and Android for the architectures with the generic values, and on FreeBSD, DragonFly, NetBSD and OpenBSD; rule 4 states where the guarantee holds. New tests cover a FIFO, a directory and a link to a device at `ita.lock`, through `discover` and the CLI, a manifest appended to while it is read, and a FIFO opened with and without the flags. O(min(n, bound)) to read a file of n bytes, as before.
