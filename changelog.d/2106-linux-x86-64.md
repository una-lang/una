- **Linux on x86-64 is a release target again** (#2106, ADR 0124 rule 31 and its amendment of 2026-11-27, accepted by the Owner): `x86_64-unknown-linux-gnu` is back in `scripts/release-targets.txt`, with its Z3 library pinned in `supply-chain/z3.lock` and shown reproducible by independent cold builds. Its native evidence, which the arm64 gate machine cannot give under emulation (no seccomp filter installs there, #1442), comes from a GitHub-hosted `ubuntu-24.04` x86-64 runner: `.github/workflows/linux-x86-64.yml` runs the `linux` and `limits-linux` legs there natively on the exact commit, the solver child's seccomp confinement installed and tested, and keeps each leg's log, manifest (runner image, kernel, processor) and digests as an artifact, which `scripts/release-gates.sh` checks through `scripts/hosted-evidence.sh` and copies into the release record. The x86-64 archive built on the gate machine must be byte for byte the one the runner checked natively. The installer installs the x86-64 archive from 0.5.3 on and refuses an earlier release there. Nothing else runs on GitHub Actions. On x86-64 the release `una` links with the image's GNU ld (`gcc-toolset-13-binutils`), as on aarch64, not rustc's default rust-lld, so that its link trace is the one the C math library check reads (#2340).
