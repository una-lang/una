- **`Files`: a grant on the current directory reaches its files again, confined as any other** (#2144, `spec/13 §5`, `spec/14 §3` rule 2; a regression of #1459, never released). The prefix of `files:.:<modes>` (or of any path that names the directory the grant is relative to, such as `data/..`), in a `--grant` flag, in the grants of an executable and in `[run] grants` of a package run as `una run .`, was held as the empty path, which no host resolves, so since #1459 every `Files` operation under such a grant ended with `NotFound` and wrote nothing. That prefix is now `.`, which resolves to the directory itself: the operation is given the canonical form of a directory inside it joined with the final component, a missing directory is still `NotFound` with no path given to the operating system, and a path that leaves the directory through a link or `..` is `Denied`, in `una run` and in native executables. No other grant changes.
