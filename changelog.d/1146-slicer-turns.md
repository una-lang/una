- **Soundness: a turn's end no longer depends on earlier code** (#1146, ADR 0117 rule 2, `spec/27 §8` rule 4). Under the real clock, the slicer of native code started only at the run's first started task and then ticked on its own 10 ms phase, so before any `start` tasks that shared a worker never yielded, and after one a turn ended 10 to 20 ms in, by how long earlier code ran. A `secret` condition that decided whether a task was started could so decide the winner of a later `first of` whose label is `public`. A turn was also timed from its start on the worker, so the root, whose turn began at `main`, carried every computation it ran alone before its first `start`, and a `secret` amount of such work could decide whether a later public deadline passed. The slicer now starts with the run's scheduler, whatever the program starts, and each turn ends 10 ms after the later of its start and the moment a second task became ready on its worker: the worker sets the end when it takes a new turn, a task queued behind a lone one moves it, both under the queue's lock, the slicer wakes at the earliest pending end, and the check point's slow path ends the turn only once the clock has reached it, one atomic load and one clock read, with the fast path unchanged.
