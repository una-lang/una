- **Soundness: a turn's end no longer depends on earlier code** (#1146, ADR 0117 rule 2, `spec/27 §8` rule 4). Under the real clock, the slicer of native code started only at the run's first started task and then ticked on its own 10 ms phase, so before any `start` tasks that shared a worker never yielded, and after one a turn ended 10 to 20 ms in, by how long earlier code ran. A `secret` condition that decided whether a task was started could so decide the winner of a later `first of` whose label is `public`. The slicer now starts with the run's scheduler, whatever the program starts, and each turn ends 10 ms after its own start: the worker sets its turn's end when the turn begins, the slicer wakes at the earliest pending end, and the check point's slow path ends the turn only once the clock has reached it, one clock read, with the fast path unchanged.
