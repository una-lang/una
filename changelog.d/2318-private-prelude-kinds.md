- **No module names the prelude's private kinds `Complex_F64` and `Complex_F32`** (#2318, `spec/29 §19`, ADR 0122 rule 49; a change of the edition `0.5` preview, for the heading "Edition `0.5` preview: changes that may need edits" of ADR 0121 rule 6; kind: U2001, U2029). The prelude declares these record kinds without `pub`, as the form of `Complex[F64]` and `Complex[F32]` that no program writes. The names pass refused them with U1001, but the type checker still found them in the prelude for every module, so `Complex_F64(re: 1.0, im: 2.0).re` returned as an `Int` got an extra U2001, `Int of Complex_F64` said "`Complex_F64` is not a unit" instead of "unknown unit `Complex_F64`", and a dependency of edition `0.4` under a root of edition `0.5` got those diagnostics where it gets none alone. Now the type checker gives no other module a kind that the prelude does not declare `pub`. `Complex[F64]`, `Complex[F32]` and `complex` do not change. Every such program was refused before and is refused now. The cost is one look at the kind's declaration when an upper-case name falls back to the prelude, O(1).
