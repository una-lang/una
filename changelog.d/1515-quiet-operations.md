- **Security (S-42): operations performed under a `secret` branch no longer show in the trace by occurrence** (#1515, `spec/26 §6` rule 4, `spec/11 §5`). An operation of a capability that accepts a label above `public`, a handler's or a host's such as `Http` under `internal`, performed under a program counter above `public`, appended one event, its arguments redacted, so the number of events and the `seq` of every later event revealed the secret. An operation performed in quiet code now appends no event to a run's trace and takes no `seq`, in both engines and in every edition, wherever its handler is declared; an example's trace keeps it, for `expect performed`, and code quiet only by the timing floor of a `within` or `first of` keeps it, as `spec/27 §5` rule 7 says (Core marks it `quiet timing`). Code quiet only by the conservative rules (a generic decision, an operation body under an effect floor, a `via` body) loses its operations' events too, though they occur whatever the secret there. A failure that an iteration deadline causes in quiet code no longer counts as the iteration's first observation of it. Still open: the slots and parks of quiet tasks (#1545); the outcomes of later public operations on host state that hidden quiet code changed are closed by S-45 (#1552). The formal re-check does not cover declarations that hold `quiet`, which now include every operation under a raised program counter.
