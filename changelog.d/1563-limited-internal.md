- **Security S-46: whether `acquire` of `std.limit` fails is `internal`** (#1563, `spec/27 §10` rule 4, ADR 0117 IF5; edition `0.4`, unreleased). The checker did not apply the rule that `Limited` is labeled `internal`, so a program could branch on `attempt @gate.acquire()` and print the result: with a hidden `acquire` under an `internal` branch before it, it printed whether that branch took the token. Now whether a call of `Limit.acquire` fails, and its payload, carry `internal`, whatever handler serves it, so `attempt` gives an `internal` `Result`. **This rejects programs that compiled before:** a public print or result chosen by whether `acquire` failed is U4003 or U4001, and `if error pass` or `if error fail` of its failure is U4002; a parameter that receives the `Result` must be declared `internal Result[Unit, internal Limited]`. The diagnostics name the call: "the condition carries whether `@gate.acquire` failed, labeled `internal`, the label `Limited` carries" (`spec/13 §3`). A program that keeps what it decides at `internal`, handles the failure in place with `if error use`, or releases it through a policy of a trusted module still compiles. The conformance cases `runtime/limiter_acquire` and `runtime/limiter_tasks` now release their printed outcomes through a policy. The check is O(1) per operation site, so the checker stays linear.
