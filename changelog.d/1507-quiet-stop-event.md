- **Security (S-39): code under a `secret` branch no longer shows in the trace through the events the runtime appends by itself** (#1507, `spec/26 §6` rule 4). A host stop, a budget, SIGTERM or `--deadline` that ended a `for ever` under a program counter above `public`, a `within` whose deadline cut its loop there, or a failing `tasks` statement that cancelled its tasks there, in the code itself or in what it calls, a call of a `secret` function value included, appended a `stop`, `timeout` or `cancelled` event and moved the `seq` of every later event, so the number of events revealed the secret. Such code now appends none, and numbers its `tasks` statements and `first of` blocks apart, so it no longer moves the `task` paths of later public events, in both engines. The run-wide budget of `--stop-after-iterations` is S-36. Still open: a `start` under a `secret` branch inside a public `tasks` statement (S-40, #1512), handler installation numbering under a `secret` branch (S-41, #1514), and the occurrence of operations of capabilities that accept `secret` (S-42, #1515).
