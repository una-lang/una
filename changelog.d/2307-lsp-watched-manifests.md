- **`una lsp` re-checks a package when its manifest or lock changes** (#2307, ADR 0063). The language server ignored `workspace/didChangeWatchedFiles`, so a saved `ita.una`, `ita.lock`, `itaty.una`, `una.toml` or `verification.lock` changed nothing in the editor until a module was saved, and the diagnostics shown were those of the old manifest. On such a change the server now checks again, at tier 1 as on a save, the package of each open module in or below the file's directory, and the package of that directory when it has diagnostics shown, so a fixed manifest clears its own; a change of any other file is ignored. A client that registers file watchers only on request (`dynamicRegistration`) is asked to watch these five files after `initialized`; a client that watches on its own, as the VS Code extension does, is not asked. A response of the client is no longer answered with a `-32601` error. The cost is one pass over the open documents per changed file.
