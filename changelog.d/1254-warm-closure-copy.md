- **Security, timing: the warm-up's tasks copy a closure object** (#1254, second part; `spec/27 §1` rule 4, ADR 0116 amendment P8 and P12; edition `0.4`, unreleased). The warm-up of #1255 ran one real task per worker before `main`, but with an integer word for its closure, so it copied nothing: the copies' pending segment (16 KiB, the largest allocation a task makes) and the task heap's slot table were first made by the program's own tasks, as often as earlier code, possibly `secret` code, had started them. The warm-up's closure is now a closure object, exported and imported as every compiled block's is, so the allocations of a public block's tasks are the same whatever earlier code started: measured per block on `--workers 1024`, the same allocation counts, bytes and size classes, page faults and stack mappings for both keys of the oracle `a_public_block_s_timing_never_depends_on_how_many_tasks_secret_code_started`. Cost: O(N) tasks for N workers once per run, as before, each copying one node; transient memory of one batch of 64 tasks, about 1.3 MiB, whatever `--workers`. The oracle at p >= 0.05 over alternating runs is owed to a quiet machine.
