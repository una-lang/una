- **Security, timing: the warm-up's tasks copy an object at the fork and at the join** (#1254, second part, which stays open until its timing oracle passes on a quiet machine; `spec/27 §1` rule 4, ADR 0116 amendment P8 and P12; edition `0.4`, unreleased). The warm-up of #1255 ran one real task per worker before `main`, but its closure and its value were integer words, so it copied nothing: the copies' pending segment (16 KiB, the largest allocation of a task) and the slot tables of the heaps on both sides were first made by the program's own tasks, as often as earlier code, possibly `secret` code, had started them. The warm-up's closure is now a closure object, exported and imported at the fork, and its value an empty list, exported and imported at the join, as the copies of a compiled block whose tasks return a list, a record or a text are. Measured with per-block counters on `main` 4af0da01, before the fix, at `--workers 1024` with the oracle's program (`a_public_block_s_timing_never_depends_on_how_many_tasks_secret_code_started`): the public block made 36,936 allocations and 19,524,286 bytes under key 0 against 36,935 and 19,524,222 under key 1, with 1,026 to 1,027 against 1,024 to 1,025 minor page faults and no stack mapping or thread start under either; the warm-up block made 24,647 allocations and 2.1 MB with none from 16 to 32 KiB, where each block of the program made 1,024, one per task, the one structural difference found. With the fork half of the fix, the warm-up block made those 1,024 under both keys; the join half was checked by a unit test, not by the counters. Cost: O(N) tasks for N workers once per run, as before, each copying one node in and one out; transient memory bounded by one batch of 64 task heaps, about 1.3 MiB, plus N empty lists in the root's heap, all freed before `main`. The oracle at p >= 0.05 over alternating runs is owed to a quiet machine; the card stays open until it passes.
