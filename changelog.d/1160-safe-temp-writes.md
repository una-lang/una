- **Security: writes under a package no longer follow a planted link** (#1160, advisory UNA-SA-018). `una fmt`, `una fix`, `una migrate`, `una ita lock` and `una fmt ita.una` used to write a temporary file at a fixed name next to the file they replace (`.<name>.fmt-tmp`, `.<name>.tmp`), following a symbolic link at that name. A repository could commit such a link and have a formatting run overwrite a file outside it. The temporary file is now created exclusively, under a name unique to the write, with mode 0600 until it takes the destination's permissions, then synced and renamed. A source that is a symbolic link is still written through onto the file it resolves to, but only when that file and its directory are inside the package: a link that leads outside it is refused, naming where it leads. `una build` writes its object file the same way, creates `target/una` one level at a time, and checks the executable's path before the linker starts: a link planted at `target`, `target/una` or the object that leads outside the package is refused, and so is any link at the executable's name. Before, it wrote the object with a write that follows a link. The proof cache stores its entries the same way, without the fsync since a torn entry fails its tag and is solved again, and stores nothing when `.una`, `.una/cache`, `.una/cache/proofs` or an entry's name is a link that leads outside the package.
