- **Security (S-40): a `start` under a `secret` branch no longer shows in the trace** (#1512, `spec/26 §6` rule 4, `spec/27 §7` rule 5). Inside a public `tasks` statement, a `start` under a program counter above `public` moved the index `k` of every later `start` of the same statement, so the `task` path `s<c>.<k>` of a later public task's events, and the worker that `k` picks, spelled out the secret, and when the block then failed it added one `cancelled` event per such task. Under `tasks at most n at once` it also took a slot, so a later public `start` waited and the interpreter's order of public events changed. Such a `start` is now quiet: its task, `s<c>.q`, takes no number, waits only for the statement's quiet tasks, and ends without its `cancelled` event, in both engines. Quiet code now numbers none of its `tasks` statements, `first of` blocks and `start`s (`qs`, `qf`, `q`), since code that is quiet without a `secret` branch, under a generic decision or an operation body, writes events whatever the secret, and a count in their paths showed how many quiet runs came before.
