- **Security (S-40): a `start` under a `secret` branch no longer shows in task paths or `cancelled` events** (#1512, `spec/26 §6` rule 4, `spec/27 §7` rule 5). Inside a public `tasks` statement, a `start` under a program counter above `public` moved the index `k` of every later `start` of the same statement, so the `task` path `s<c>.<k>` of a later public task's events, and the worker that `k` picks, spelled out the secret, and when the block then failed it added one `cancelled` event per such task. Such a `start` is now quiet: its task, `s<c>.q`, takes no number and ends without its `cancelled` event, in both engines. Quiet code now numbers none of its `tasks` statements, `first of` blocks and `start`s (`qs`, `qf`, `q`, S-44, #1546), since code that is quiet without a `secret` branch, under a generic decision or an operation body, writes events whatever the secret, and a count in their paths showed how many quiet runs came before. Still open (#1545): a quiet task holds a slot of its statement's bound, so under `tasks at most n at once` it can make a later public `start` wait, which in the interpreter reorders public events, as a park inside quiet code does. Every task of one quiet `start` now runs on one worker, a cost of quiet code only.
