- **una-z3 links Z3 from a verified copy** (#1925, lane S). The build script hashed the Z3 library at the path that `UNA_EMBED_Z3` or `UNA_Z3_LIB` names and then linked it by its directory, so the linker read the file again after the digest check, and searched that directory first for the C++ runtime: a `libstdc++.a` (Linux) or `libc++.a` (macOS) planted beside the pinned library was linked unverified while the library's digest still matched. The build script now copies the library into a directory of its own output that holds the copy alone, hashes and checks the copy, makes it read-only, and names only that directory to the linker. The digest check, its messages, the two variables and the C++ runtime directives of both targets are unchanged. Tests run the build script's code on temporary directories: a library beside the given one is never in the link's search, a change of the given file after the check never reaches the link, and what an earlier build left in the directory is removed; reverting to the old behavior fails them. On macOS a planted `libc++.a` beside the library broke the link before and is ignored now.
