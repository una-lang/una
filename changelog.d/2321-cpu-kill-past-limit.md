- **A solver child killed by the kernel at its hard processor-time limit is reported as `cpu`** (#2321, #2322): on Linux, when a solver child's own end by `SIGXCPU` comes later than the second between its soft and hard processor-time limits, the kernel ends it by `SIGKILL`; the parent now reads a `SIGKILL` it did not send, from a child that used at least its soft limit (from `wait4`), as `unknown` with reason `cpu` instead of `crash`. A coincident outside kill of a child already past its soft limit (the OOM killer, macOS jetsam, a `kill -9`) is reported the same way, since the parent cannot tell them apart. Neither is ever an answer, and no limit changes. The child's signal-waiting thread runs on a small stack (64 KiB); in the case no real limit reaches, a `SIGXCPU` pending before Z3 installs its handler (#2322), that handler would run on this stack, and a stack overflow there would be a `crash`, never an answer.
