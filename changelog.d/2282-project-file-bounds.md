- **The size bounds of project files are measured on the raw bytes, by every command, while the file is read** (#2282, #2292, `spec/30 §1` rule 4; kind: U7008, U7009). The 1 MiB bound of `ita.una` and `itaty.una` and the 16 MiB bound of `ita.lock` were measured on the decoded text by the commands that read through the source database (`una check`, `una fmt`, `una ita lock`, `publish` and the others), where each `\r\n` counts one byte, and on the bytes by `una ita add`, `una ita update <name>` and the registry: a manifest of more than 1 MiB whose `\r\n` line ends brought it under the bound was accepted by `una check` and `una ita publish` and refused by `una ita add`. Every reader now measures the bytes of the file as written, and every command reads a project file within its bound, at most one byte past it, so a file past its bound is never held whole in memory; the refusal states the number of bytes the file holds. The fuzz targets `ita_lock` and `registry_mirrors` gain a leg on the decoded entry that every command uses, and a test refuses a decoded text (`.text()`) passed to a project-file reader, which would decode the file twice. O(min(n, bound)) to read a file of n bytes.
