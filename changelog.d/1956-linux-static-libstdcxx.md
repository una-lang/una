- **The Linux `una` no longer needs `libstdc++.so.6`** (#1956, ADR 0124 rule 1). una-z3's build script asked for `libstdc++` as a shared library, and the release flag `-static-libstdc++` does not reach an explicit `-lstdc++`, so the aarch64 Linux `una` of `scripts/release.sh` needed the system's `libstdc++.so.6` and `scripts/load-commands.sh` refused it. The C++ runtime of the solver is now linked statically on Linux (`static:-bundle=stdc++`), and the shipped `una` depends dynamically on glibc and on GCC's unwinder `libgcc_s.so.1`, which every Rust program for Linux on glibc loads, as before. Every Linux build of `una`, a development build included, now needs the toolchain's static `libstdc++.a` (on Fedora and RHEL, the package `libstdc++-static`). `scripts/load-commands-test.sh` gains two Linux canaries: a dynamic `libstdc++` fails as `una`, a static one passes. macOS is unchanged.
