- **Proposed: concurrency for servers** (#896, ADR 0117, Proposed). Edition `0.4` would run tasks as coroutines on a few worker threads, so that a waiting request parks only its task, with no `async` or `await`. It would gain `within d`, a time limit on an expression that fails with `Timed[E]` or `Deadline`; `first of`, where the first branch to succeed wins; and `tasks` with `start`, a bounded, dynamic number of tasks that cannot fail, all ended before their scope. `Http` grants could carry rate and concurrency limits, enforced below every handler without deadlock, with `HttpError.RateLimited` when the wait queue is full, and `std.limit` would cover rates computed in code. Operations that a deadline or a race can cut would be checked under the timing label, and there would still be no task values. Nothing is implemented yet.
