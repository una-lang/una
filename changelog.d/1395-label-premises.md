- **Host premises in the build report** (#1395, part 3 of #566, ADR 0094 rule 5). `una report` gains the key `premises`, after `assumptions`: the premises on the host that a package's acceptance rests on, H1 to H4, the `Env` note and the new H5 (what an operation answers through a binding where it is labeled `l′`, and whether it fails, is a function only of the arguments and of the part of the host state at or below `l′`), each with its statement and what the package uses it for: the host operations its headers list that the premise covers (a package capability with a host capability's name does not count, and `tcb.host_capabilities` now tells them apart too), or, for H5, every operation a function's or a handler's header labels with `gives`. These premises are assumed of the deployment, never proven; a labeled operation is accepted on the checker's rules alone until the formal model covers labels (#563). The human report prints them under `assumed of the host:`. `spec/13 §6` states the key and the premises, and `docs/plan/formal-track-status.md` lists H5. The key is additive, and the schema stays `una.report/2`.
