- **Resolution and the `una ita` commands** (#997, ADR 0122 rules 23 to 25 and 57, `spec/30 §6` and `§10`). `una ita lock` resolves by minimal version selection over what is held offline, each path dependency as its directory holds it, within the bounds of rule 23, the root's needs counted as a release's. A registry need is refused with the new code U7013, no resolution, since this release holds no registry's per-name state, and a source is refused as a whole rather than resolved from a partial view; an avoided version with no later release and a bound exceeded are U7013 too. Every change of the lock is printed as a review before it is written: per package, its origin, versions, digests, the ceiling granted, and what its code uses at tier 0, also as `changes` in `una.ita/1`. New: `--dry-run`; `una ita update [<name>...]` with `--cooldown`, `--now` and the `--accept-...` flags; `una ita add <name> [<version>] [--as] [--from]`, which writes `ita.una` and the lock only when the resolution succeeds, and so, in this release, never for a registry need; and `una ita verify`, which verifies each locked registry package again in `vendor/ita/` and in Itaoca. `una ita fetch` and rule 26's check of two release statements join with the registry client. No command opens a connection or starts a program.
