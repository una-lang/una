- **A `together` block checks its bookkeeping and its task starts against the memory budget** (#777, ADR 0113 step 4). In native code, the block's result list is reserved exactly before its first batch, each batch's state before it forks, each task's start before its thread starts, and each adoption of a batch's events before it is made, so a block whose bookkeeping or starts would pass the budget stops with U6003 at the block instead of reaching the allocator's hard ceiling. A task's heap is torn down whole as its thread ends. A debug build of the runtime checks the bound with a high-water mark of the heap, each start and adoption against what it reserved, and that no copy of a block is made while one of its tasks runs code. The interpreter does not change.
