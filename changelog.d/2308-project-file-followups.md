- **Project files that are not regular files are refused before they are read, and the bounded read reports only what it knows** (#2308, #2309, #2310, #2311, #2312, #2313, `spec/30 §1` rule 4; kind: U7008, U7009). A FIFO at `ita.una` made `una ita remove`, `add`, `update` and `yank` wait forever for a writer. Every command now reads `ita.una`, `ita.lock` and `itaty.una` only when the path names a regular file, through a link or not; it opens the file without blocking and refuses a FIFO, a device or a directory at once ("is not a regular file"). A file that grew past its bound while it was read was reported as holding one byte more than the bound; it is now reported as holding more than the bound. Every reader refuses a file left unread past its bound, whatever length it records. Rule 4 now separates a file read on its own, never held whole past its bound, from a file inside an archive, which is held within the archive's bound. A reader no longer accepts a borrowed `&str` other than a literal, so the decoded text of a file cannot reach it and be decoded twice, directly or through a variable; the source guard also refuses a decoded text wrapped again in `Text::Written`, `SourceFile::new` or `SourceDb::add`. The fuzz targets `ita_lock` and `registry_mirrors` gain a leg that reaches the bound's refusal. New tests read a file of exactly its bound from disk, a capped read of an endless source, a link to `/dev/zero` and a FIFO. O(min(n, bound)) to read a file of n bytes, as before.
