- **The installer: the C library as the system runs it, a 64-bit userland, and root** (#1938). On Linux, `install.sh` reads the C library from the running system instead of from a file being there: a glibc system that also has musl's loader installed (Debian's `musl` package) now installs, and musl is still refused, by its `ldd --version`, by musl's loader when `getconf GNU_LIBC_VERSION` shows no glibc, and when the aarch64 loader `/lib/ld-linux-aarch64.so.1` that `una` needs is missing, is musl's (gcompat) or does not answer `--version` as glibc's. A 32-bit userland on a 64-bit kernel, which reports aarch64, is refused before any download (`getconf LONG_BIT` must be 64). As root, the installer refuses, before any download or removal, a `UNA_HOME` that another user could change: a symbolic link for `UNA_HOME`, a directory it writes in or a file it writes, and a directory there or above it that is not owned by root or is writable by its group or others (one above may be writable by others when it is sticky, as `/tmp` is); a file there that is not root's or that others can write; and a `TMPDIR` (default `/tmp`, which may be sticky) that another user could change, since the archive is checked and unpacked there. It works on the physical path, refuses when `id -u` cannot be read, and no longer runs the installed `una` as root. Only owners and mode bits are read, not ACLs. Every refusal is tested on fake machines, on `uname -m` both `aarch64` and `arm64`.
