- **`F64` in contracts: the verifier's FloatingPoint encoding** (#1033, #819, ADR 0114 rule 8, `spec/29 §8`). In edition 0.3, float literals, `nan()`, `infinity()`, `+ - * /`, unary `-`, `==`, `!=`, the orders, the IEEE comparisons, `abs()`, `sqrt()`, the classifications and `to_f64()` of an integer are in the refinement language, encoded exactly as SMT-LIB `Float64` with `RNE`, so `kind Unit01 = F64 where it.ieee_ge(other: 0.0) and it <= 1.0` and `ensures result <= 1.0` are proven or refuted with the run-time semantics. A query with an `F64` term is in the logic `ALL` with the fixed step budget 5,000,000; every other query is byte-identical. Integer obligations of float code keep only the float facts they need (the cone), so an index beside float arithmetic stays a cheap integer query. A float query heavier than the bound of 4 is U5002 before solving, and every float `unknown` names its reason and repairs. Counterexamples show an `F64` by its rendering (`"0.1"`, `"-0.0"`, `"nan"`).
