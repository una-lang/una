- **Release checks with the solver built into `una`** (#1277). The C math library check (#1092) and the load-command check (#1103) keep their full strength on what a Una program contains, the native runtime `libuna_rt.a` and every executable that `una build` links, and now also on `una` built without the solver, which `scripts/no-libm-build.sh` builds for the check so that the interpreter's code is held to the rule on its own. The release `una`, which holds Z3 (ADR 0124), is checked against two explicit lists of its own: `scripts/no-libm-una.txt`, the math functions Z3 imports in its search heuristics (`exp`, `exp2`, `log`, `log2`, `pow`), each of which must also be imported by the Z3 library `una` was linked with, and `scripts/load-commands-una.txt`, the C++ runtime it loads (`/usr/lib/libc++.1.dylib` on macOS; glibc's `libm.so.6` on Linux, not yet observed). Any other name or load command still fails. New canaries, `scripts/no-libm-test.sh` and `scripts/load-commands-test.sh`, link small programs that must fail each check in every scope, and run before the checks in the `build` gate and in `scripts/local-ci.sh`. `docs/spec/29-numerics.md` §6 rule 5 carries a dated note on the scope.
- **The macOS Z3 library is reproducible** (#1277). Two builds of the same objects gave two libraries because the archive's member headers carried each object's time, owner and group; `scripts/build-z3.sh` now builds with `ZERO_AR_DATE=1`, and two cold builds give one digest, which `supply-chain/z3.lock` records for `aarch64-apple-darwin`.
