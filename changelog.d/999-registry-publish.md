- **`una ita publish`, `yank`, `audit`, `watch`, `bundle` and `unbundle`** (#999, ADR 0122 rules 33, 36.2 and 41 to 43, `spec/30 §15`). `publish` refuses what rule 43 names, a package in a git repository while the check for uncommitted changes is not available, and any diagnostic of a tier 1 check; reads the name's verified state at a fresh checkpoint; prints rule 26's advice for a public header the earlier release of the line had; refuses authority that grows within a major line; signs the release statement with the owner's keys of `~/.una/keys/`; and sends it to the source that `publish to` names, which stops for now since there is no https transport yet. `yank` sends a yank signed by the owner's threshold the same way. The registry client now reads yanks and advisories in a name's chain, each verified with its thresholds, and resolution skips a yanked or advised release and takes a fix that a lifting advisory names with no cooldown. `audit` reports U7014, once per package, for a locked release that is yanked, under an advisory, or signed after a stated compromise, and for a pending recovery or a key change of its owner, at a fresh checkpoint. `watch` follows an owner's chains from a position kept in Itaoca and reports a registry's broken promise to log a submission. `bundle` and `unbundle` carry a lock's registry packages, with the registry's files that prove them, to an air-gapped machine, where everything is verified at the lock's resolution point before Itaoca is written, and the stored checkpoint never moves backwards. Plain `http://` is refused wherever a URL is read, and `una ita add` refuses a `--from` other than the source that serves a package's owner.
