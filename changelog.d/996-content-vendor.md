- **Itaoca, vendoring and offline loads** (#996, ADR 0122 rules 17 and 27 to 32, `spec/30 §9`). Every command that loads a package of edition `0.4` checks each registry package of its lock, with no network: it must be in the vendor directory or in Itaoca (U7011 otherwise), and, read again on every load, each file once into memory through a descriptor opened with `O_NOFOLLOW` and checked against the entry listed, the bytes read must have the locked digest before any of them is used, and only those bytes are used afterward and a stored provenance that verifies against the lock: the source's pinned root, the cosigned checkpoint of the lock's resolution point, the release statement's digest and signature by the locked key, and its inclusion proof (U7010 otherwise). `una ita vendor` copies each locked registry package from Itaoca into `vendor/ita/<source>/` with its provenance, writing the verified bytes into a fresh private directory (mode 0700, files created exclusively, permissions set through the descriptor, everything synced) that is then renamed into place, as Itaoca stores packages, and verifies the copy as a load does; a vendored copy that does not verify is never replaced. Path dependencies are read through descriptors too. No command opens a connection for a package, which a test of the sources checks. New codes: U7010 (a package or its provenance that fails verification) and U7011 (a locked package in neither place). Registry packages are still not mounted in a program, and no command fetches yet.
