- **A `[contracts]` lock string with escapes, or a multi-line one, is read where it is written** (#727, ADR 0092 rule 8). Each position of a lock clause was placed one byte past the opening quote plus its offset in the decoded value, so after an escape such as `\"` every position fell too early in `una.toml`, and a condition was quoted from the wrong bytes: `e valid(sk` for `valid(sku)`. Each position is now mapped through the string's escapes, its trimmed first newline and its line-ending backslashes, and a condition is quoted as the string reads, `name == "a"`, in U7002, in U3023 and in the `contract_lock` goal. A string that cannot be read back to its value is U7002 at its entry, never a lock left out. Locks are matched by their parsed conditions, as before, so no package is accepted or rejected differently. The id of a `contract_lock` obligation is hashed from its goal, so it changes for a locked condition that is written after an escape, holds one, or is in a multi-line string, and only there.
