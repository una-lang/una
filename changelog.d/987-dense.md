- **Dense values in edition 0.4, a preview: `Array[T]` and `Matrix[T]`, the front end, the checker, the verifier and the interpreter** (#987, ADR 0120, `spec/29 §17`). `Array[T]` is the one fixed-length array, of any element type; `Matrix[T]` takes `F64` or a fixed-width integer element type (U2002 otherwise). The prelude gains `array`, `array_filled`, `matrix`, `matrix_filled` and `matrix_diagonal`. Reads (`get`, `at`), updates in place (`edit x.set(...)`, copy on write), O(1) views (`slice`, `row`, `column`, `block`, `transpose`) and `compact`, element-wise `+`, `-`, `-x` and a scalar `*` and `/` (with the element type's `overflow` obligation on fixed-width elements), `map`, `zip_map`, `update`, `fold`, `to_list`, and on `F64` elements `multiply_elements`, `divide_elements`, `sum`, `row_sums`, `column_sums`, `dot`, `norm2`, `all_finite`, `multiply`, `multiply_array`, `add_product`, `add_scaled` and `scale`; on integer elements `sum_exact` and `dot_exact`. `*` and `/` between two dense values are U2001, with `multiply(by:)` and `multiply_elements(by:)` as repairs, and no scalar is broadcast. Sums add in 32 lanes combined in a fixed tree, and inner products in blocks of 64 `fma` terms, so a dot product and the matching element of a matrix product are the same bits; both sizes are unsettled points of the preview. Shapes and integer elements are in the refinement language, and the shape frame keeps a matrix's rows and columns through a loop that only updates it. In edition 0.4, a declaration named `Array`, `Matrix`, `Tensor` or `Lu` is U1002. `Tensor`, `Lu` and the factorizations, the other element types, and native code follow; until then `una build` reports a program with a dense value as not compiled yet.
