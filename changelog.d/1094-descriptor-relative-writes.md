- **Security: vendoring and Itaoca write relative to directory descriptors** (#1094, `spec/30 §9` rule 5). The writes of `una ita vendor` and of the Itaoca store now open their base once and each directory below it relative to the one above, create the fresh private directory with `mkdirat`, open it with no link followed and require it to be private and owned by the process's user, create every file and subdirectory with `openat` relative to the descriptor of its directory, and rename the result into place relative to the parent's descriptor with `RENAME_NOREPLACE` on Linux or `RENAME_EXCL` on macOS, which refuses anything already at the name. On Linux, someone who could rename entries of the parent could swap the fresh directory's path for a symbolic link between two checks, and files written in that window were created where the link pointed; the swap was detected before the rename, so nothing was moved into place. Writes no longer go through any path, so that swap redirects nothing. The wrappers are new in `una-sys` (`dir`); `una-project` stays free of `unsafe`.
