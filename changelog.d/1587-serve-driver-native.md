- **The driver of the `serve` section in native code** (#1587, ADR 0123 rule 16, `spec/31 §7` rules 4 and 5), edition 0.4 preview, built only by the toolchain's own test builds, as a program of the language form is (`spec/31 §1` rule 10): every other `una build` of a package with a `serve` section still fails closed with the usage error of rule 5, and so does a `within` of the section. The executable's description carries the section as `"serve": {"module": ..., "within": ...}`, and the flag that lets a run take `serve:` grants is renamed `serve_grants` in it. The executable runs the driver as the interpreter does, engine code equivalent to the program of rule 4: for a reply, a failing `handle` (`500`, its payload never sent) and a reply that `reply` refuses, its bytes and its trace are the interpreter's, byte for byte, and without a `serve:` grant it stops before anything starts with the usage error `una run` gives (rule 1). Each request costs one `next`, one closure of one captured value, one `start`, one move of one reply right and one `reply`, O(1) beside `handle` and its bytes.
