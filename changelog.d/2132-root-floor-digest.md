- **The root-version floor holds the digest of the root metadata's text, so a place that holds no key cannot poison it** (#2132, security, `spec/30 §14`, ADR 0122 amendment of 2026-11-19). The floor's digest covered the whole signed note, signature lines included, and a client ignores the signature lines of keys it does not know. A mirror directory, or a bundle given to `una ita unbundle`, could therefore serve an honest root version with one junk signature line; when no accepted checkpoint named that version (a lock made under an earlier root version, and no latest checkpoint served), `una ita fetch` accepted it and stored the digest of the altered note, and every later command against the honest registry was refused as a fork (U7010) until the user removed a file. The floor now stores `<n> text sha256:<hex>`, the digest of the text that the root keys sign, and every comparison with the floor uses it: every form of one root text compares equal, and another digest at the floor's version is another root text, which a threshold of root keys signed. A floor of the earlier form, `<n> sha256:<hex>`, is still read and compared as it was stored, by the digest of the whole note; it is replaced once, under the floor lock, by the digest of the text of the same note, only when the chain walked and verified holds its version with exactly that note. The digest that `sources` pins, that a checkpoint names and that the lock records is unchanged.
