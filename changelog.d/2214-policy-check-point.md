- **Security: a policy call is a check point of the schedule of started tasks** (#2214, review H1 of PR #2212, `spec/27 §8` rule 5). A policy call runs its `via`, whose code the label rules do not check, but the checker returned from the policy's branch before it recorded the call as a check point, so rule 5 of #1684 never saw it: a `via` whose work depended on its argument ordered the public prints of started tasks by that argument, at `secret` as at `internal`, in the interpreter under both clocks and natively under `--virtual-time`, and the program was accepted with an empty report. The call is now recorded with the deep label of its argument joined with the program counter: above `internal`, in a program that starts tasks, it is U4002; at `internal` it is accepted and listed in the report's `information.timing` as a `task switch` (the residual of #1708); with a `public` argument nothing changes. Elaboration builds the call as any other call (`push_call`). Programs that release data above `internal` through a policy inside a package that starts tasks are now refused, whatever the policy's `to` label.
