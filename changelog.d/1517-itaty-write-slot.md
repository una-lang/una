- **Security: the registry service bounds the writing of a response and its connection threads** (#1517, `una-itaty`, in no release). A connection gave back its slot before its response was written, the write had no timeout, a file was read whole into memory before it was sent, and `serve` started a thread for every connection and stopped when one could not start, so clients that never read a large file could hold its bytes and a thread each without limit. A connection now holds its slot to its response's last byte; a response is written with no write waiting more than the write timeout (60 seconds) and, past it, at least 64 KiB per second on average, the mirror of the rule for bodies; a file is sent from the open file in parts of 64 KiB, the version that was opened, whole; `serve` takes the slot before it starts the connection's thread, so it runs at most `max_connections` of them and answers a connection past the bound 503 with no thread; and a thread that cannot start closes its connection and the loop goes on.
