- **The driver of the `serve` section in the interpreter** (#1587, ADR 0123 rule 16, `spec/31 §7` rules 4 and 5), edition 0.4 preview, run only by the toolchain's own test builds, as a program of the language form is (`spec/31 §1` rule 10): `una run` and `una build` of a package with a `serve` section still fail closed with the usage error of `spec/31 §7` rule 5. The driver is engine code equivalent to the program of rule 4, not Una source or Core IR: the serve threads start before it, it takes each request with `next` and starts a task per request that calls `handle`, answers `500` with an empty body when `handle` fails, never its payload, and ignores a failure of `reply`, so a `BadReply` ends in the task's `500`; at a host stop the requests in flight drain and `on_stop` runs on the main task, exit code 0, and at the hard stop the rights held are answered `503`, `on_stop` does not run and the run ends with U6007. Each request costs one `next`, one `start`, one move of one reply right and one `reply`, O(1) beside `handle` and its bytes. Its bytes and its trace are those of the program of rule 4 written out, byte for byte. Native code's driver, `una build` of the section and the `within` of the section come with the next parts.
