- **The reactor** (#972, ADR 0117 rules 3 and 4, `spec/27 §2`). In native code, an `Http` request of a task runs on the task's own worker, and each wait on its connection parks the task on one reactor thread, over `kqueue` on macOS and `epoll` on Linux, which wakes it when the connection is ready, its deadline passes, a host stop reaches it or its task is cancelled. A request to a server that never answers no longer holds a helper thread, so thousands of requests wait at once, and an interrupted request's connection is closed as its task resumes. Name resolution and the connection itself still run on the I/O pool (`--io-threads`), interruptibly, and a literal address starts no resolver thread. Outcomes, failures and traces do not change, and the interpreter is unchanged. Each parked request holds one socket, so a run that reaches its limit of open descriptors gets `Unreachable` for the connections it cannot open. `una-sys` gains `poll`, the `kqueue` or `epoll` instance behind a safe interface, with one-shot registrations and a close-on-exec descriptor, and `signals::wake_pipe`; it stays under its 1,200-line cap.
