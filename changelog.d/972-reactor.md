- **The reactor** (#972, ADR 0117 rules 3 and 4, `spec/27 §2`). In native code, an `Http` request of a task runs on the task's own worker, and each wait on its connection parks the task on one reactor thread, over `kqueue` on macOS and `epoll` on Linux, which wakes it when the connection is ready, its deadline passes, a host stop reaches it or its task is cancelled. A request to a server that never answers no longer holds a helper thread, so thousands of requests wait at once, and an interrupted request's connection is closed as its task resumes. Name resolution and the connection itself still run on the I/O pool (`--io-threads`), with the wait there covered by the request's deadline; a job whose request was cancelled or expired opens nothing, resolver threads are bounded by `--io-threads` and never start past a deadline, and a literal address starts no resolver thread. The sockets of parked requests are capped process-wide at the soft limit of open descriptors less a reserve of a quarter of it (at least 64), with a first-come, first-served wait for a place, so a server that never answers can no longer make `Files` operations fail. Outcomes, failures and traces do not change, and the interpreter is unchanged but for the same bound on resolver threads. `una-sys` gains `poll`, the `kqueue` or `epoll` instance behind a safe interface, with one-shot registrations and a close-on-exec descriptor, `signals::wake_pipe` and `io::descriptor_limit`; it stays under its 1,200-line cap, at 1,199 lines.
