- **`una fix` lists the `let`s it leaves when a package moves to edition `0.5`** (#1629, ADR 0137 rule 11; a change of the edition `0.5` preview, for the heading "Edition `0.5` preview: changes that may need edits" of ADR 0121 rule 6; kind: U7007). In a package of edition `0.5`, `una fix` rewrites each `let` to `const` and each `let edit` to `var`, the first repairs of their U7007, in blocks, `when` arms and `together` branches, keeping comments and layout, and a second run finds nothing to rewrite. It now leaves the rewrite of a `let` in a module that does not parse (a module with a syntax error), listed as a skipped U7007 with the reason `does not parse`, until the module's own repairs make it parse in a later round; before, it rewrote such a `let` too, and `let const = 2`, where `const` is a name that edition `0.5` rejects, became `const const = 2`. It also lists, as a skipped U7007 with the reason `doc comment`, each `let` in a backtick span of a doc comment, which no check reads, and leaves it. The two reasons join those of `una.fix/1`'s `skipped` entries, whose schema does not change. A new test moves every edition `0.4` package of the repository (the conformance corpus, `tests/serve_runs`, `formal/gen` and the examples, those of `una.toml` through `una fix` in edition `0.3` and `una migrate`) to edition `0.5` with `una fix`, and checks that it reports what the package fixed in edition `0.4` reports at tier 1, with the same exit status, that its modules are those of edition `0.4` with the words rewritten, and that a second run changes nothing. Editions `0.1` to `0.4` do not change. The listing is O(size of the modules).
