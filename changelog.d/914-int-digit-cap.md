- **Security: integer parsing is bounded at 4300 digits** (#914). Converting a text of d digits to an `Int` took O(d²) time, so a program parsing untrusted text could be made to spend quadratic time in one call. `parse_int` now fails with the new `ParseError` variant `TooLong`, and `to_int` returns `None`, for an optional `-` and more than 4300 digits, the bound JSON already had (`NumberTooLong`). The check scans the text once, before any conversion, so both cost O(b). One constant, `MAX_INT_DIGITS`, serves JSON, `parse_int` and `to_int`, in both engines. In editions `0.2` and `0.3`, a `when` that names each `ParseError` variant without an `else` arm becomes non-exhaustive and must handle `TooLong`.
